# Source Video Locator MVP — 问题与开源方案调研总结（最终版 v2）

> 依据：全项目源码通读（locator_service.py 2984 行 + evidence_localize.py 亲读，engine/media/infra/device/domain/api 由只读代理逐文件覆盖，41 份档案文档）+ 两轮 GitHub 调研（约 70 个仓库，关键结论已亲验）。未修改、未新增任何文件。

## 一、项目现状快照

「编辑片（解说/混剪）片段 → 2h 原片素材起点反向定位」的 Windows 桌面产品（Vue3+Electron + FastAPI + PyInstaller）。现役指标：**严格命中 147/150**（dense_recheck 默认开后）、定位中位误差 0.83s（长镜头 1.38s）、建索引 22-31min/片（其中 **CPU 抓帧占 78%、DML 推理仅 18%**）、locate ~30min/片、渲染 26s（workers=6 后）。

架构主干：原片 1fps DINOv2 CLS-384 全片索引 → 编辑片 2fps 两级切分（白闪/字卡守卫）→ 逐帧 Top1 检索 + 15s gap 聚类 + finloc 0.4 阈值 longest_run 精化 → 置信六信号加权 → **12 条修复腿**（fast_global → dense_recheck → OCR 字牌 → 序列 DP → 时序修复 → 冲突修复 → 歧义降档 → 连续起点 → 退化门 → 镜头拆分 → patch 精排 → ISC 重排）→ XFeat 起点精修 → 人脸标注 → 四通道导出/成片渲染。

## 二、四大结构性瓶颈（含代码级根因）

**① 查询段跨镜头（83%，21/41 段中跨镜头）— 采纳层死结**
检索按帧独立 argmax，跨镜头查询天然散到多个源片位置；"切出子镜头后选哪个"没有可靠信号（max-sim 必选错、TopK/三通道判负、OCR/语音被用户否决）。

**② 同场景多机位切点盲（长镜头漏切）**
像素帧差/TransNetV2/CLS 三通道对"外观不变的场景切换"全失明。CLS 存在性 AUC 0.919 但切点时刻只有 29% 对；OmniShotCut 段级 9/15 但帧级 1/5、CPU 31min。

**③ 边界时刻精度无尺子**
只有点估计（中位 0.83s），没有帧级容差判据量化"边界到底准不准"。

**④ 置信体系结构性饱和**（通读逐信号核验）
clean 段 purity/margin 恒 1.0、consist 实为余弦量、stability 在 run≥4s 即饱和、coverage_quality 单 run 恒 1.0 ⇒ conf_v2 对 clean 段算出 ≈0.92 必不降档——"自信错答"分不开是机制性的。

## 四、对应开源方案（两轮调研收敛）

**① 跨镜头死结 → 绕开挑选、直接对齐**
- [SamsungLabs/Drop-DTW](https://github.com/SamsungLabs/Drop-DTW)：带 drop cost 的 DTW，错误子镜头被"丢弃"而非挑选——与 max-sim 机制正交；底座 [wannesm/dtaidistance](https://github.com/wannesm/dtaidistance)（1.3k★，活跃，C 加速多维子序列 DTW）。可在现役 384 维特征离线验证。
- [vl2g/MATR](https://github.com/vl2g/MATR)（ICCV 2025，MIT）：唯一"片段→未剪辑视频时刻"任务级开源（双阶段 DTW+boundary queries），级联候选。
- [facebookresearch/sscd-copy-detection](https://github.com/facebookresearch/sscd-copy-detection) + [facebookresearch/vsc2022](https://github.com/facebookresearch/vsc2022)：帧级描述子→帧间投票→段聚合路线。
- 学术现状：2024-2026 VCL 有码的仅 InR2R3（无 license）；SS-VCL/FiGVCL 确认无码。

**② 多机位切点 → 换信号源**
- **PyAV `export_mvs` 压缩域运动向量**（[PyAV-Org/PyAV](https://github.com/PyAV-Org/PyAV)，3.3k★，BSD，Windows wheel）：机位切换=MV 场翻转，时刻精确的外观无关信号——调研确认**无现成 MV→SBD 成品**，需自研约百行。
- 先验证用 [AdamSpannbauer/python_video_stab](https://github.com/AdamSpannbauer/python_video_stab)（vidstab，780★，纯 OpenCV）的全局运动轨迹突变。
- [pyannote/pyannote-audio](https://github.com/pyannote/pyannote-audio) 说话人切换（时刻精确，但属音频信号——落地需用户点头）。

**③ 边界精度 → 先补尺子**
- **SoccerNet mAP@δ**（[SoccerNet/SoccerNet](https://github.com/SoccerNet/SoccerNet) 的 `Evaluation/ActionSpotting.py`）：δ={0.1,0.25,0.5,1,2}s 网格，纯 Python 零依赖。
- dense_recheck 固定 ±4s 窗 → [facebookresearch/vq2d_cvpr](https://github.com/facebookresearch/vq2d_cvpr) 式**从命中峰向两侧扩张到相似度跌落**；[matrix-profile-foundation/matrixprofile](https://github.com/matrix-profile-foundation/matrixprofile) 1D 互相关做亚秒修正。
- 同构冠军方案 [arturxe2/T-DEED](https://github.com/arturxe2/T-DEED)（2h 长视频特征输入秒级 spotting）可当修复链新腿；监督形式抄 [showlab/UniVTG](https://github.com/showlab/UniVTG) soft 边界标签。

**④ 置信 → 三件套（无 GT、非饱和、只吃距离分布）**
- **AS-Norm cohort 归一化**：[wenet-e2e/wespeaker](https://github.com/wenet-e2e/wespeaker) `score_norm.py`（Top-K 距离自适应 z-score，"自信错答杀手"）。
- **k-reciprocal 互惠一致性**：[layumi/Person_reID_baseline_pytorch](https://github.com/layumi/Person_reID_baseline_pytorch) `re_ranking.py`。
- **KNN/Energy/Mahalanobis OOD**：[kkirchheim/pytorch-ood](https://github.com/kkirchheim/pytorch-ood)（DINOv2 同源先例 [AnomalyDINO](https://github.com/dammsi/AnomalyDINO)）。
- conformal 库（MAPIE/TorchCP/crepes）全卡"需 GT 校准集"，排除。

**XFeat 退化族（快速运动/遮挡/大尺度）**
零成本加固（OpenCV `USAC_MAGSAC` + XFeat 自带 semi-dense + [GMS](https://github.com/jiawangbian/gms-feature-matcher) 预过滤）→ SIFT+LightGlue 并联 → ALIKED 替换测试（[Shiaoming/ALIKED](https://github.com/Shiaoming/ALIKED) + [cvg/LightGlue](https://github.com/cvg/LightGlue) + [LightGlue-ONNX](https://github.com/fabio-sim/LightGlue-ONNX)）；基准工具 [danini/homography-benchmark](https://github.com/danini/homography-benchmark)。

**人脸身份门（多脸侧+暗光）**
[roboflow/trackers](https://github.com/roboflow/trackers)（3.96k★，无 torch 的 ByteTrack/OC-SORT：采样帧邻域内跟踪+ArcFace 缝合）；SER-FIQ 质量挡灰带（[pterhoer/FaceImageQuality](https://github.com/pterhoer/FaceImageQuality) 机制）；上限升级 [mk-minchul/AdaFace](https://github.com/mk-minchul/AdaFace) 或 w600k_r50；暗光 A/B 用 [SCI-ONNX-Sample](https://github.com/Kazuhito00/SCI-ONNX-Sample)。

**smart render（DTS/PTS 非法，严格解码 1975/4513）**
- [huerlima/smartcut](https://github.com/huerlima/smartcut)（上游停更后的活跃 fork，MIT，2026-10 仍在推，⚠️ 0 star 个人维护——**抄算法模式，需自行接管**）：`cfr_snap.py` 专修"copy↔重编接缝 DTS 空隙/编码器 B 帧延迟不一致"+ stts 不变量断言。
- 重编段 `bframes=0`（[AMF #433](https://github.com/GPUOpen-LibrariesAndSDKs/AMF/issues/433)：画质 bug + 消除接缝时间戳重排，一石二鸟）；ffmpeg `setts` BSF mux 层钳 DTS 兜底；[DeepRegular/SmartCut](https://github.com/DeepRegular/SmartCut) 11 坑清单当 checklist（GPL 只读不抄码）。

**抓帧/性能（78% 耗时的根治）**
管道换 yuv420p（带宽减半）+ ffmpeg 侧先 scale 再过管道；[abhiTronix/deffcode](https://github.com/abhiTronix/deffcode)（220★，活跃）/PyAV 进程内解码消灭 ~800 次 spawn；选型横评 [python-decoders-benchmarks](https://github.com/NevermindNilas/python-decoders-benchmarks)；DML 前处理融合进 ONNX 图（Resize+归一化子图，防静默回退 [onnxruntime #23154](https://github.com/microsoft/onnxruntime/issues/23154)）。⚠️ 两者都动 preprocess 语义 ⇒ 必须 bump feature_version 全量重建+三指标验收。DINOv3（[facebookresearch/dinov3](https://github.com/facebookresearch/dinov3)，11.6k★）权重需申请+自定义许可+无官方 ONNX，仅远期候选。

**PyTorch AMD 现状（只读了解）**
[microsoft/DirectML](https://github.com/microsoft/DirectML) 已进**维护模式**、torch-directml 冻结在 PyTorch ≤2.4；Windows+AMD 跑 PyTorch 的现实主路是 ZLUDA（[lshqqytiger/ZLUDA](https://github.com/lshqqytiger/ZLUDA)，整合包参照 [stable-diffusion-webui-amdgpu](https://github.com/lshqqytiger/stable-diffusion-webui-amdgpu)）；ROCm 原生不支持 RX 6750 GRE（RDNA2）；**kornia 在 torch-directml 上不可用**（cumsum 缺算子、双线性插值出错）⇒ XFeat 强制 CPU 的既定决定正确；OmniShotCut 若接线用 torch CPU 轮。
