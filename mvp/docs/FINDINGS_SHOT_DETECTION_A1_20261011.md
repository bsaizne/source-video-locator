## 0. 一句话结论

**现役 `scenes.npy` 在画面确认的边界尺子上只找回 23% 的真边界**（P 0.71 / R 0.23 / F1 0.35，
±1.0s）；其中约 **2.8 倍**的召回损失是**参数**造成的（`z_thresh=1.5` 一腿就压掉一半以上），
调参能把召回提到 **0.63-0.65** 且精度不降反升（留出窗已验，不是过拟合）；
但快切片（test2）有 **44% 的真边界在 1fps CLS 序列上连局部极大都不存在** ⇒ 那部分**任何阈值都救不了**，
必须换信号：**像素/颜色通道同尺实测 P 0.71 / R 0.86 / F1 0.78**，且成本几乎为零（解码才是成本主体）。
⇒ **A1 的调参可以做但只到半程；A2 值得立项开码。**

## 1. 边界尺子（§5.1 的「先有尺子」）

| 项 | 值 |
|---|---|
| 覆盖 | 4 片 × 10~14 个 12s 窗 = **44 窗 / 540s**（全片 31124s 的 **1.7%**） |
| 选点 | 分层随机（seed 20261011，避开首尾 30s）+ test2 定向 4 窗（已知漏切区 3285-3333） |
| 标注 | 4fps 接触表（192×108 缩略图 8×6 格，每格标绝对秒）**逐格目检**，边界=新镜头首格 |
| 条目 | **150 条**，其中 conf=high **125 条**（其余为正反打/手持漂移/变焦歧义） |
| 入库 | `mvp/scripts/shot_detect/boundary_gt_v1.json`（+ `windows_v1.json` 选点清单） |
| 容差 | 现役 CLS 是 **1fps**（边界粒度 1s）⇒ **主口径 ±1.0s**；±0.5s 只对像素通道公平，并列报数 |

⚠️ 覆盖边界（不是欠账，是这把尺子的量程）：
- 目检在 192×108 缩略图 / 4fps 上做 ⇒ 对「像素几乎不变的匹配剪辑、软切」覆盖不足 ⇒
  **像素通道的 R 偏乐观、CLS 的 R 偏悲观**。交叉核需 A3（PySceneDetect 当第三方尺子）。
- 短于 0.25s 的镜头不保证入尺。
- test1 只有 **3 条**高置信边界（该片这 10 段 6 段是单镜头长拍）⇒ **test1 的读数不可外推**（教训 ⑥）。
- 精度在两半窗之间抖动大（现役 P：选参半 0.882 / 留出半 0.583）⇒ **P 差 <0.1 不可读**，R 稳。

## 2. A1 分腿消融（现役 → 每腿单独改）

| 腿 | overall P/R/F1 (±1.0s) | R 分片 2mkv/test1/test2/test3 | 全片边界数 |
|---|---|---|---|
| **现役**（cut.15 / z1.5 / cw7 / ms3.0） | 0.707 / **0.232** / 0.349 | .48/1.00/.11/.26 | 2671 |
| 只 min_shot_s 3.0→1.0 | 0.698 / 0.240 / 0.357 | .48/1.00/.11/.29 | 2713 |
| 只 context_window 7→15 | 0.846 / 0.264 / 0.402 | .57/1.00/.13/.29 | 2466 |
| 只 z_thresh 1.5→0.6 | 0.772 / **0.488** / 0.598 | .67/1.00/.36/.61 | 4747 |
| 只把 z 判据关掉 | 0.759 / **0.504** / 0.606 | .71/1.00/.37/.61 | 5246 |
| 只 cut_abs .15→.30 | 0.784 / 0.232 / 0.358 | .48/1.00/.11/.26 | 2444 |
| ms1.0 + z 关 | 0.722 / **0.664** / 0.692 | .76/1.00/.56/.81 | 6978 |
| ms1.0 + z 关 + cut.30 | 0.786 / 0.648 / **0.711** | .76/1.00/.53/.81 | 5910 |
| ms1.0 + z 关 + cut.40 | **0.823** / 0.632 / **0.715** | .71/1.00/.53/.77 | 5288 |

读法（教训：多旋钮必须分腿归因）：
- **`z_thresh` 是主凶**：单这一腿 1.5→关，召回 0.232→0.504（**+0.27**）。机理 = 局部 z-score 拿
  「自身邻域均值」作基线，而快切段的邻域本身就全是切 ⇒ 真切的 z 只有 0.5~1.2，被 1.5 判据系统性否掉。
  现役参数下 **79~94% 的真边界邻域 z < 1.5**（`work/shot_gt/a1_results.json`）。
- **`min_shot_s=3.0` 单改几乎无效（+0.008）**，但与「关 z」**强交互**（合起来 0.664）：机理 =
  z 判据先把候选杀光，最短镜头合并腿自然无从下手。⇒ 单旋钮消融会互相掩蔽，必须成对验。
  且 test2 平均镜头 2.2s < 3.0s ⇒ `min_shot_s=3.0` 在该片上是**结构性摧毁**（把真镜头并成假镜头）。
- `cut_abs` 与 `context_window` 单独动基本不改召回，只改精度。

## 3. 天花板：哪一部分阈值救不了

| 片 | 候选集可达召回（±1.0s，= 真边界处存在 s 局部极大） | 调参后实得 R | 差 |
|---|---|---|---|
| 2mkv | 0.762 | 0.76 | 贴顶 |
| test1 | 1.0（n=3，不外推） | 1.00 | — |
| **test2** | **0.557** | 0.53 | **44% 的真边界在 1fps CLS 序列上没有任何局部极大** |
| test3 | 0.806 | 0.81 | 贴顶 |

同时：真边界邻域内 s 的中位数高达 **0.70~0.88**（`<0.15` 占比 0~1%）⇒ **不是「CLS 看不见这些切」，
而是「看见了但没有可分离的尖峰位置」**——快切段整段都是高距离，峰不定位。
⇒ 这是**信号选型 + 采样分辨率**问题，不是阈值问题。CLS 通道的召回天花板 ≈ 0.55（快切片）~0.81。

## 4. 留出窗对照（防「扫参扫到噪声上」）

每片按时间奇偶分半：偶半=选参集（22 窗）、奇半=留出集（22 窗）。只在选参集上选 TOP5，再到留出集验：

| params | 选参窗 P/R/F1 | **留出窗 P/R/F1** |
|---|---|---|
| cut.30 z.6 ms1 cw7 | .880/.620/.727 | **.756/.574/.653** |
| cut.40 z.6 ms1 cw7 | .896/.606/.723 | **.775/.574/.660** |
| cut.20 z.6 ms1 cw7 | .846/.620/.715 | **.721/.574/.639** |
| 现役 scenes.npy | .882/.211/.341 | **.583/.259/.359** |

⇒ 调参增益**在未见窗上复现**（F1 0.36→0.65，R 0.26→0.57），不是过拟合。
留出集事后最优 = `cut.30 / z 关 / ms1 / cw7`（P .783 / R .667 / F1 .720）。

## 5. A2 预演：像素通道值不值得立项

像素序列 = 160×90 / 10fps 解码，相邻帧 32-bin 灰度直方图 L1 与 mean-abs-diff 各半加权，
局部极大 + NMS(0.4s)。同一把尺子、同一批窗：

| 通道 | P/R/F1 @±1.0s | P/R/F1 @±0.5s | 备注 |
|---|---|---|---|
| 现役 scenes.npy | .707/.232/.349 | .585/.192/.289 | 2671 边界 |
| CLS 纯 s 阈值 0.3（调参后） | .786/.648/.711 | .689/.568/.623 | 5910 边界 |
| **像素 mix 阈值 0.15** | **.706/.864/.777** | .693/.848/.763 | 153 边界（窗内） |
| 像素 mix 阈值 0.20 | .752/.800/.775 | .737/.784/.760 | 133 |
| 朴素并集 CLS∪像素 | .461/**.944**/.619 | — | **不能这么合**：召回 0.944 但精度塌到 0.46 |

定向区复核（test2 3285-3333，48s，已逐格目检）：

- 现役 `scenes.npy`：**2 段**（3285→3323 宽 38s、3323→3370 宽 47s）
- 目检 GT：**21 个边界**（平均镜头 2.2s）
- CLS 纯 s 阈值 0.3：17 个边界
- 像素 mix 阈值 0.15：**19 个边界**，与 GT 逐条对齐（缺 3324.25/3326.0，多 3313.3 一类 0.3s 位移）

**成本**（决定 A2 是否可兑现的关键）：300s 片段整段解码实测 17~18s，**与输出 300 帧还是 3000 帧几乎无关**
（1fps 全分辨率 18.4s / 1fps 缩放 16.9s / 10fps 缩放 17.6s）⇒ 成本主体是**解码本身**，像素直方图是零头。
现役建索引已经在为全片解码付钱，A2 的边际 ≈ 再一遍解码 ≈ **+5min/5000s 片**（相对现役 22~31min），
且像素解码是纯 CPU、与 DML/MPS 推理可并发 ⇒ 墙钟增量可近零。

## 6. 建议（等拍板，本批未动 runtime）

1. **A2 立项开码**（推荐）：索引期加像素边界通道，与 CLS 融合。融合规则**不能是朴素 OR**
   （§5 精度塌到 0.46），建议「像素定候选位置 + CLS 距离作第二证据 + NMS + min_shot」，
   派生版本位 `scn1→scn2` bump（**只重算场景表/事件表，不重抽 CLS 特征**）。
   验收 = 本尺子（F1 显著 >0.78）+ 三指标不降 + **导出实得**并列口径 + `check_export_plan_invariants`
   + 成片多模态复验。
2. **A1 调参批**（可单独先做，但别当「已修好」）：关 z + `min_shot_s=1.0` + `cut_abs .30~.40`
   是一处小改动，把召回 0.23→0.63；代价 = **全片边界数 2671→5288~5910（翻倍）**，
   下游边界吸附、取材扩宽、事件表派生全受影响 ⇒ 属 runtime 改动，须跑后端全套 + 三指标 + 导出实得，
   并重新评估 B 护栏（K=2.5）是否仍需要。
3. **A3 当第三方尺子**：接 PySceneDetect content-aware 只作**评测对照**（不进 runtime、不加产品依赖），
   用来核 §1 那条「目检尺子对像素通道偏乐观」的偏置有多大。
4. B 护栏（`material_expand_rel_cap=2.5`）**保留**：A 修好后它仍是多一道保险，且是成片症状的唯一现网缓解。

## 7. 本批未证面（如实登记）

- 尺子是 1.7% 抽样，且 test1 仅 3 条高置信 ⇒ 跨片不外推；A2 落地前应在**未见片**上再攒一批窗。
- 目检通道与像素通道同源（都看像素变化）⇒ 像素 R=0.864 是**偏乐观上界**（§1 已述），需 A3 交叉。
- 留出只做了「窗」的二分，**没有做「片」的二分**（4 片都参与了选参）⇒ 参数跨片泛化未独立验。
- 成本数字来自探针（单进程 `iter_frames`），**不是生产索引路径**；A2 实现时要同脚本双臂实测。
- 本批只回答「能不能救 / 值不值得投」，**未测**「场景表变好之后三指标与成片是否变好」——那是 A2 的验收。
