# FINDINGS：查询段跨镜头 —— 三片验证通过，但「主因」表述要挂条件（2026-10-19 续80）

> 起因：续79 交接件把「查询段跨镜头」写成**可能是定位误差 1.38s 的主因**，但那条结论只用 **test1 一片**、
> **只逐帧看了 3 段**、阈值 0.10 是**拍的**、且**从没和外片/时长混杂/置信度做过对照**。
> 本轮就是给这个承重前提补做可证伪检查。**零 `mvp/src` 改动、未出包。**

## 0. 一句话

**这个问题是真的、而且比我原先写的更值钱**（跨镜头段吃掉 **66%** 的总误差），
**但「主因」这句要挂两个条件**：① 只在**误差意义上的大错**上成立，中位误差上只有 2/3 的段能看出来；
② **现役 `confidence` 对它完全没有判别力**（AUC 0.54 / 0.49），
⇒ 用户拿到一条 `HIGH` 的跨镜头结果时**没有任何提示**。这一条是**新增的真问题**，不是旧结论的复述。

## 1. 我补做了什么（对照续79 的三处薄点）

## 2. 核心读数（三片合并，N=95）

### 2.1 相关性够硬

| 检验 | 读数 |
|---|---|
| Spearman(段内 max CLS 距离, \|err\|) | **+0.487** |
| 随机基线（\|err\| 打乱 2000 次） | 均值 +0.005 / sd 0.105，**经验 p < 0.0005**（0/2000 超过观测） |
| 留一片交叉验证 | 留 test1 +0.631 / 留 test2 +0.367 / 留 test3 +0.394 —— **三折全部同向** |
| 偏相关（剥掉段内帧数 n） | +0.399 |
| 偏相关（剥掉段时长 dur） | +0.398 |
| 对照 Spearman(段时长, \|err\|) | +0.319（混杂真实存在，**但剥不掉主效应**） |
| 段长分层内仍成立 | dur 0~2.5s +0.333 · 2.5~5s +0.444 · 5~12s +0.525 |

### 2.2 值多少（按生产口径 0.50）

| 分组 | n | \|err\| 中位 | ≤2s 命中 |
|---|---|---|---|
| 全批（现役口径） | 95 | 1.13s | 60（63%） |
| **段内 max_d > 0.50（生产阈值能判出的）** | 44 | — | — |
| 段内 max_d ≤ 0.50 | 51 | — | — |
| 段中跨镜头（阈值 0.10 口径） | 54 | 1.85s | 30（56%） |
| 无跳变 | 17 | **0.52s** | 16（**94%**） |

- **误差质量集中度**：`max_d > 0.50` 的 **44 段（46%）吃掉了全部误差的 66%**（7073s / 10728s）。
- **大错（\|err\|>10s）共 22 段**：阈值 **0.50 抓到 20 段（召回 91%，精确率 45%）**；
  阈值 0.10 抓到 22 段（召回 100%，精确率 28%）。
  ⇒ **生产现成阈值就够用**，不需要调。

### 2.3 ⭐ 新问题：现役 confidence 对这个结构性缺陷完全无感

| 检验 | 读数 | 含义 |
|---|---|---|
| AUC(`confidence_score` → 是否 ≤2s 命中) | **0.544** | 0.5 = 瞎猜 |
| AUC(`confidence_score` → 是否 \|err\|>10s 大错) | **0.486** | 0.5 = 瞎猜 |
| 对照 AUC(`max_d` → 是否大错) | **0.823** | 信号本身很强 |

- 逐片 `Spearman(conf_score, |err|)` 符号还不一致（test1 **+0.291** 正向 / test2 −0.335 / test3 −0.138）
  ⇒ 合池后 **−0.016**。**相关在这种小样本上不可信，所以用 AUC 判。**
- 具体形态：**「段中跨镜头 + 现役报 HIGH」共 39 段**，其中 **11 段（28%）是大错（>10s）**。
  最刺眼的几条：

| 片 | id | \|err\| | confidence_score | 档位 | 段内 max_d |
|---|---|---|---|---|---|
| test1 | t1r14e | **379.00s** | 0.934 | HIGH | 0.799 |
| test2 | t2r05b | **108.00s** | 0.865 | HIGH | 0.834 |
| test1 | t1r30a | 62.33s | 0.958 | HIGH | 0.775 |
| test1 | t1r14d | 36.47s | 0.933 | HIGH | 0.734 |

**这就是产品级的真缺口**：错 379 秒的结果被打上「高置信」。用户看到的是确定性，实际是不确定性。

## 3. 必须挂的三个条件（别把这条读成「找到主因了」）

1. **只有 3 段被逐帧看过**（t1r02 / t1r08a / t1r14e，续77）。其余 92 段仍是**统计判据**
   （CLS 距离）——虽然三片交叉验证与分层都稳定，但**「真跨镜头」这个标签本身仍未被逐段画面确认**。
2. **中位误差上只是部分成立**：逐片「段中跨镜头」的 ≤2s 命中率是 test1 57% / test2 20% / test3 70%，
   test3 的中位（0.88s）反而不比全批（1.13s）差。**是「大错集中」而非「普遍退化」。**
3. **阈值仍是人为选的**。0.50 是生产现成值，但这不等于它标定过；分位数 p50=0.378 / p75=0.743，
   说明段内 max_d 本身是连续量，**「跨镜头 vs 不是」不该二分**。

## 4. 与既有档案的关系（不重开已判负的四条）

- 这条**不是** `_subshot_relocalize` 那条线。09-05 的结论「采纳层无可靠选择信号，max-sim 必选错」**不受影响**
  （见 `FINDINGS_SUBSHOT_TRIGGER_MEASURED_20261019.md`）。本轮证明的是**另一个粒度**：
  不使用 subshot、**只把「这一段有跨镜头」如实标出来**，就已经有价值。
- 也**不是** TopK / 切分器 / 非外观信号那四条。那四条仍是「判负/不立项」，重开条件不变。
- 本轮**没有**、也**不建议**改 `confidence` 公式：**公式冻结 + 不标定是护栏**
  （`DECISIONS.md` 2026-09-01）。若要做，属于**新立项**且必须用户点头 —— 口径见 §5。

## 5. 建议（需拍板，我没动手）

| 选项 | 做法 | 代价 | 我的看法 |
|---|---|---|---|
| **A. 只标注、不改置信度** | 在结果里加一个**独立字段**（如 `query_cross_cut: {max_d, at, n_sub}`），UI 展示「本段内含画面跳变，起点可能只对应其中一段」；`confidence` 字段一格不动 | 纯增量字段 + UI 一行 | **推荐**。不碰冻结公式，不碰定位逻辑，可回退 |
| B. 改 confidence 公式 | 把跨镜头信号计入置信度 | **撞护栏**（公式冻结） | 不建议，需先解冻 |
| C. 改定位主路径 | 段内切分再定位 | 已判负（09-05），且死结在采纳层 | 不重开 |
| D. 只在导出层提示 | 导出时按阈值标「高风险段」 | 等于立项③的一部分 | 与立项③合并考虑 |

⚠️ **A 的边界**：这是「如实告诉用户不确定性」，**不是提高精度**。三指标（严格/主 span/场景）**不会因此变好**，
`measure_shot_recall.py` 读数不变。**不要拿它当精度改进报数。**

## 8. 我本轮差点犯的错（留档）

- **预期写反**：我在 `qcut_thresh.py` 里先写了「阈值升到 0.50 召回会塌」，实测是 **召回 91%、精确率升到 45%**。

  **小样本 + 强非线性时，AUC 比相关系数可靠。**
