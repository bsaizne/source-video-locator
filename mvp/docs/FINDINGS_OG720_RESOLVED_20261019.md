# FINDINGS：`og720-720` 相似度「自相矛盾」已结案（2026-10-19，续73）

> 上游挂账：`HANDOFF_20261016_export_smoothness.md` §6.5 / §10.3「一处算法给 0.08、另一处给 0.97，
> 两个数打架，没查是谁错」——自 2026-10-16 起挂了三轮会话。
> **结论：两个数都不错，是三个不同问题被当成了同一个量。** 零 `mvp/src` 改动，纯只读复核。

## 0. 一句话

`og720-720` 是**成片末尾的定格卡**（真值 **15 帧 / 0.626s**；缓存口径 17 帧 / 0.709s，多出的 2 帧是已知补帧假象；帧间自相似 0.993）。
「0.97」= 它在**成片**里找得到（末帧定格，`max` 口径）；「0.08」= 它在**解说最后几秒**里找不到
（短窗 `max` 口径，实测 0.096~0.118）；「0.73」= 它在**解说全片**里最好也就这样。
**三个数分别回答了三个不同的问题，把它们并排比较才产生了"矛盾"这个假象。**

## 1. 素材本体（先把被比较的东西钉住）

| 读数 | 值 | 出处 |
|---|---|---|
| 帧数 / 时长（ffprobe 真值） | **15 帧 / 0.626s** @23.976 | `og_clips.json` |
| 帧数 / 时长（特征缓存口径） | 17 帧 / **0.709s** | `og_feats.npz` + `blocks.json` |
| 帧间自相似 mean / min | **0.9927 / 0.9875** | 本文实测 |
| 像素帧差中位 `d_med` | **0.19**（35 段里最小；其它段 0.57~22.6） | `blocks.json` |
| 自身切分块 | 1 块（0~17），无段内切点 | `blocks.json` |

> ⚠️ **+2 帧是已知假象，不是素材属性**：`blocks.json` 走 rawvideo 口径，**35 段全部恒多 2 帧**
> （差集分布 `{2: 35}`）—— 交接件 §5.2 已记过「rawvideo 字节计数器每份恒定多 2 帧（ffmpeg 把 0.083s
> 起始空隙用首帧填满）」。实测 og720 的**前 3 帧两两 cos = 1.0**（完全同一帧），正是补帧形态。
> ⇒ **真时长 0.626s（15 帧）**；本文其余读数用特征缓存的 17 帧口径算，**结论不受影响**（多 2 帧同画面）。

⇒ **它是一张几乎全静止的画面**（定格/字幕卡），不是一段有动作的镜头。这决定了后面所有口径的形态。

## 2. 三个数各自的口径（逐条可复现）

对 `og720` 的 17 帧，逐帧取与目标的最大 cos，再看聚合方式：

| 目标窗口 | 中位 | 最大 | 说明 |
|---|---|---|---|
| 成片·最后 1s | **0.9728** | 0.9769 | ← **0.97 的来源** |
| 成片·全片 | **0.9728** | 0.9769 | 与上同（成片里就这一处能找到） |
| 解说·全片 | 0.7282 | 0.7426 | ← **0.73**（解说里找不到同一帧，只是"不冲突"的底噪） |
| 解说·最后 1s | 0.0959 | 0.1062 | ← **0.08 的来源族** |
| 解说·最后 5s | 0.1182 | 0.1269 | 短窗 `max` 的中位就在 0.09~0.12 |
| 解说·最后 10s | 0.1182 | 0.1269 | 同上 |

**0.97 的自洽性**：`og720` 17 帧在成片里的最佳匹配时刻全部落在 **64.03~64.10s**（成片总长 64.20s）
⇒ 与**成片最后 0.7s** 逐帧高度一致；`成片末帧 vs og720 末帧 cos = 0.9625`。
**0.08 的自洽性**：解说最后 5s 的逐帧 `max` = 0.118/0.115/0.127/0.123/0.126 …，
四舍五入即 0.12；换成 `centroid` 口径（对窗口求质心再算 cos）则 = **0.0926~0.1069**
（成片同口径最后 1s = 0.8446，最后 5s 掉到 0.2634 —— 因为末段只有末帧是那张定格）。
⇒ **0.08 与 0.97 是「同一素材 vs 两部片」的两个问题，不是同一个量的两次测量。**

**穷举验证**：把目标窗口按 1/2/3/5/8/10s 逐秒滑动，中位落在 0.06~0.12 的窗口**确实存在**——
解说 1s 窗 @22s = **0.0801**、成片 1s 窗 @35s = **0.0813**、解说 2s 窗 @57s = **0.0780**、
解说 1s 窗 @0s = 0.0846、成片 1s 窗 @59s = 0.0887 …（`probe_og720b.py`）。
⇒ **口径族可复现**；但**具体是哪一行代码**给出的 0.08 无法还原（见 §7 边界）。

## 3. 反证：没有任何一个 35 段组合能自然得到 0.08

把 35 段 og 素材逐段对解说 / 成片算 `max` 中位并排序：

- **对解说**：最低三段 = `og2897-2898` 0.479 · `og3068-3070` 0.654 · **`og720` 0.728**；
  **全段最低值 0.479，没有任何一段低到 0.08。**
- **对成片**：全段最低值 **0.868**。

⇒ 0.08 **不可能**来自「og720 对整部片」的口径，只能来自**短窗**（≤5s）或**质心**这类聚合。
这条把「谁算错了」这个提法彻底排除：**没有人算错，是问法不同。**

## 4. og720 在成片里为什么只有 0.07s

| 事实 | 读数 |
|---|---|
| 素材时长 | **0.626s（15 帧）** / 缓存口径 0.709s（17 帧，含 2 帧补帧） |
| 成片内匹配时刻范围 | 64.03~64.10s = **0.07s 窗** |
| 成片末尾帧间相似（63.5~64.2s，21 帧） | mean 0.834 / min **0.111** |

⇒ 素材 0.626s 压进成片 0.07s，**比例 ~9:1**，不是等比映射；同时成片末段 21 帧里并非全静止
（min 0.111 说明末段内有真切换）。**这与「成片末尾是同一定格被最后引用一次」完全一致**，
也与已知结论「`og720` 排在 reel 末段」自洽。

## 5. 口径层面的教训（已浓缩进 `STATE.md` `Known Issues` 工程教训速查 ㉑）

1. **"A 与 B 相似度 X" 不是一个良定义的量**，必须先固定四件事：
   **① 比谁对谁（方向）② 目标窗口多大（全片 / 段 / 短窗）③ 逐帧 max 还是质心 / 逐帧配对 ④ 聚合用中位还是均值。**
   本次四个自由度里换任何一个，读数能从 0.08 跑到 0.97。
2. **"两个数打架"先查是不是两个问题**，别先假设有一方算错——本轮三轮会话挂账的成本，
   全部来自没先做这张口径表。
3. 极短且高度静止的素材（帧间自相似 >0.99）**天然会把短窗口径压到低值**：
   它只有一张画面，跟任何"没这张画面"的窗口比都接近正交。
4. **同一素材的「帧数」也有两个口径**：`og_clips.json`（ffprobe）= 15 帧 / 0.626s，
   `blocks.json`（rawvideo 字节数）= 17 帧 / 0.709s —— **35 段全部恒多 2 帧**（差集 `{2: 35}`）。
   这是 2026-10-16 交接件 §5.2 已定性的假象（ffmpeg 用首帧填满 0.083s 起始空隙），
   **别再把它当成"素材真的多了 2 帧"去解释任何结论**。引用时长前先说清用的是哪个口径。
