## 1. 做了什么（一句话）

**判据一格未动**，只把场景边界时刻从 **1fps 索引网格**换成**像素腿的 10fps 原始候选时刻**，
并把「场景起始边界的融合强度」落成侧车表 `scene_strength.npy`。

验收读数（test1 真索引，全片 8221s）：**943 场景不变** · `scene_feats` **逐字节相同** ·
**373/943** 条边界真的离开了网格 · `|Δ|` 最大 **0.500s**（= 1fps 半格，正是吸附上限）。

## 3. 设计要点（为什么这样改）

### 3.1 默认路径**零改变**是硬约束

所有 scn3 能力都走**可选出参**，不传参时逐字等于 scn2。理由：
`scenes.npy` 有多个下游（`exporters` 吸附/切分、`evidence_localize` 扩池、`events` 派生），
一旦默认行为变了，回归面会从「边界精度」扩散到「召回 + 导出计划」两整块。

### 3.2 连续覆盖不变式靠**同一个 `starts` 数组**保证

`scenes[k,1] = starts[k+1]`（而不是各自独立算 `times[b-1] + 1/fps`），这样相邻场景端点**严格相等**，
不会被浮点算成 `1.3999999 vs 1.4000001`。实测 `max gap = 0`。

### 3.3 单调守卫：宁可退回网格，也不产生零宽/倒序场景

原始时刻理论上 `f(j) <= f(j+1)`（吸附误差 < 0.5 帧），但同位置两腿强度打平时可能相等。
因此 `cand > t and cand > prev` 才采用，否则退回 `times[a]`。

### 3.4 侧车「宁可丢也不修」

`scene_strength.npy` 长度与 `scenes` 行数**必须严格相等**，否则 `_load_scene_strength` 返回 `None`。
理由：错位的强度比没有强度更危险——下游会拿它标「低置信边界」，错位等于把强度贴到错的场景上。
写侧车失败也只降级（warning）不让建索引失败。

### 3.5 `scene_feats` 与时间区间的 1 帧不一致（**明确保留**）

`scene_feats` 仍按**帧索引区间** `[a:b]` 求均值；边界时刻前移后半帧时，按时间筛帧
（`evidence_localize` 的 `(times >= a) & (times < b)`）可能把边界那**一帧**划给前一个场景。

**选择保留，不修**。理由：修了会让 `scene_feats` 漂移 ⇒ 场景级召回的 top-K 与 `min_sim` 门跟着变，
把一次**纯精度修复**变成一次**召回语义变更**。保留则 `scene_feats` 与 scn2 **逐字节相同**，
召回侧零风险。这个不一致已在 `build_scene_table` docstring 里写明。

## 4. 本轮我踩的两个坑（**别再踩**）

### 坑① 改错了位置：像素腿在**构造 items 时**就把时刻吸掉了

第一版我在「NMS 之后」记录原始时刻 —— 但那时 `items` 里存的已经是 `float(times[j])`（吸附后），
原始时刻在那一步就丢了。结果 `raw_out` **全空**、边界**一条没动**，
被等价性验证的「至少有一部分边界真的动了」断言当场抓住。

### 坑② 修错的方式：把 items 改成原始时刻 ⇒ **顺手改了 scn2 的判定**

改对位置后我直接把 `items.append((float(t), 1.0))`，结果 **场景数从 943 掉到 930**。
根因：NMS 是**按时间**去重的，items 的时刻变了 ⇒ NMS 结果变 ⇒ 判定变了。
这已经超出「只改精度」的范围。

**最终形态**：`items` 继续存 `float(times[j])`（与现役逐字一致），原始时刻走**并行字典** `raw_by_snap`，
完全不参与判据。这样才算真正做到「判据一格未动」。

### 坑③ 测试自己写错：拿 scn3 结果当 baseline 去比 scn2

等价性测试第一版写成 `a, _ = build(...)` / `b, _ = build(..., boundary_time_out={})` 然后断言 `a == b`，
必然失败。等价性要断的是「**新增可选参数不改变默认输出**」，基线必须再跑一次**默认调用**得到。

> 共同教训：**「默认路径不变」这件事只能靠「同一输入跑两次默认调用」来证**，
> 不能靠「跑一次默认 + 跑一次新功能」。前者的对照量是确定性，后者是两套语义。

## 8. scn4 追加：CLS 腿独立语义门（立项② 方案 A2，2026-10-18 同日夜）

> 本文档原范围是 scn3（立项①+③）。本节追加当夜完成的 **scn4 = 立项② 方案 A2**。
> 代码笔 `b6e9113`。

### 8.1 做了什么

CLS 腿的持续性门从「灰度直方图 `block_*`」改为「像素门 **OR** 语义门」：
`semantic_block_stats` / `semantic_gate_ok` 在 **CLS 向量**上算同构的前后块距离，
与像素门取**或**。同时 `cls_cut_abs` 0.30 → 0.40（与语义门**耦合**，见 8.4）。
版本位 `scn3 → scn4`。

### 8.2 为什么（图证）

**正反打换人时灰度直方图几乎不变**：同一场景、暗调、两人衣着色近。
读图 `v2_test1_5413.png`（5fps 细采样，test1 5408.5–5418.3）：

- **5411.3 → 5411.5**：金发女子（红毛衣）→ 男子（灰衣），GT **5411.46**
- **5415.3 → 5415.5**：男子 → 女子，GT **5415.46**

现役在这两处最近边界偏差 **2.85s / 6.85s**（都没命中）；语义门补回后 **0.46s / 0.46s** 命中。

### 8.3 为什么门取「或」不取「换」

两类真切点的机制**不同**，单门必漏一类：

| 类型 | 灰度直方图 | CLS 语义 | 像素门 | 语义门 |
|---|---|---|---|---|
| 正反打换人（5411/5415） | **几乎不变** | 明显变 | 杀 | **放** |
| 快速蒙太奇换景（4573.3 / 6682.4） | 大 | 峰可能不够强 | **放** | 杀 |

实测：换成**纯语义门**会丢掉 test2 4573.3 / test3 6682.4 —— 这两处我已读图确认是真切点
（`lose_test2_4573.png`：4573.1 三人坐沙发全景 → 4573.3 两人近景换机位；
`lose_test3_6682.png`：6682.0 少年特写 → 6682.4 中年男子特写换人）。

### 8.4 cls_cut_abs 与语义门是**耦合的一对**

全片实测（`probe_a_decouple.py` / `probe_a_global.py`，test1 8221s）：

| 配置 | 尺子 TP/FP/FN | 全片边界 |
|---|---|---|
| 现役 cut.30 + 像素门 | 109/25/16 | 942 |
| **只提 cut_abs 0.40**（语义门关） | 112/**38**/13 | 850（−9.8%） |
| **只在 0.30 加语义门**（A1） | 111/**28**/14 | **1045（+10.9%）** |
| **A2 = cut.40 + 语义门（采纳）** | **111/25/14** | **912（−3.2%）** |

- **只提 cut_abs 是纯亏**：FP 25→38。它的作用只是**替语义门做粗筛**（挡弱峰）。
- **只在 0.30 加语义门（A1）不可接受**：尺子上只 +3 FP 看着无害，但全片 **+103 条边界（+10.9%）**。
  导出侧 `split_clips_at_boundaries` 按边界拆段 ⇒ 导出段数会涨一成。**尺子 6.6% 覆盖看不到这个代价。**
- **A2 是唯一两个口径都不亏的档**：多切对 2 条（TP+2、FN−2）、FP 持平、全片边界反而少 3.2%。

### 8.6 本轮我连续犯的四个错（全留档）

**错①：只看 F1 涨了就判「有正收益」。** v1 探针 F1 0.842→0.863，我没拆增益来源就说「值得接线」。

**错②：又只看 R 没涨就判「判负」。** 拆解出「救回 0 条」后，我直接宣布立项② 判负。

**错③：真正的根因是探针有 bug，我却拿去给别人判死刑。** v1 的 `blocks_cls(feats, k+1)` 把
**CLS 网格帧索引**当成特征行号，而语义门必须按**绝对时刻**取块（与生产 `gate(t)` 用
`searchsorted(pix_t, t)` 同理）。索引错位 ⇒ 算的根本不是那一段 ⇒ 把两处真切点杀掉。
**修好之后结论翻转为「有正收益」。**

**错④：多模态复核是事后补的。** 用户先问「多模态复核了吗」，我才去读图；读图直接推翻了我的判负。
这已经是档案里记过的第 N 次同类错误（FINDINGS §8.1、§11.2 都记过「判归因必须读图」）。

> **结论性教训**：只要结论是「某通道/某门对某类切换无效」，**必须先用 0.2~5fps 细采样读到画面**，
> 否则不许下判负。数字只能告诉我「分数变了」，不能告诉我「切的是不是真东西」。
