## 3. 真正的死结：**采纳层没有可靠的子镜头选择信号**

这是整条线的核心，必须单独说清：

> **`research_subshot_scale.py` 的「16/16 逐子改善」是 oracle 口径**
> （`best_gap_sub` = 各子镜头命中**离 GT 中点**的最小距离）。**runtime 里没有 GT。**

runtime 只能按 **max-sim** 挑子镜头。而：

| t2r02b 子镜头 | 内容 | sim | 是否是 GT 正确子镜头 |
|---|---|---|---|
| A (BOUGHT/Jacob) | 人脸特写 | **0.625（最低）** | ✅ **是** |
| B | 乡村房屋区 | 0.770 | ❌ |
| C | 洒水器区 | **0.853（最高）** | ❌ |
| E | 暗色林地 | 0.805 | ❌ |
| F | 暗色纹理 | 0.809 | ❌ |

⇒ **max-sim 必选错误子镜头。** 多模态复审进一步坐实了机制：
编辑帧烧录字幕拼出叙事（EVERYONE / CROP / WITH / FOR…），
**「正确子镜头」由叙事/文字语义决定，不由画面特征突出度决定** —— 语义重心与视觉 sim **解耦**。

## 4. 为什么「今天发现 83% 段内跨镜头」不推翻这个结论

| | 09-05 | 今天 |
|---|---|---|
| 段内跨镜头的段数 | 四片 16 段（判据：多镜头蒙太奇，整段 gap>15 且子镜头≥3） | test1 **21 段**（判据：段内 max CLS 距离 >0.10 且在段中） |
| 判据宽严 | 严（要求 ≥3 子镜头且大 gap） | 松（任何 >0.10 的段中跳变） |
| **采纳层选择信号** | **无（max-sim 会选错）** | **同样无** |

**范围变大 ≠ 死结消失。** 21 vs 16 说明「这类段比我原先以为的多」，
但我方在**采纳层**依然没有「哪个子镜头才对」的信号。
把 fallback 升为主路径，只会让**更多段**走进这个「选错」的分支。

## 5. 那今天这轮到底带出了什么新东西

不是「应该重开 subshot」，而是三条**口径层**的推论（都还没验证）：

1. **长镜头定位误差中位 1.38s，主因可能在查询侧单元划分，不在源片侧切分精度。**
   这一条与档案「边界线四条路径查到底」的结论**不冲突**——那四条说的是「源片侧切不出更细的边界」，
   今天说的是「查询侧本来就不该按现在的粒度当单元」。**两者可以同时成立。**
2. **三指标 HIT 口径宽（主+子 span 任一覆盖即算）掩盖了起点误差** ——
   这解释了为什么「严格 135/139」与「起点误差中位 1.38s」能共存。
3. **要真正解决，缺的不是更好的切分器，是「哪个子段才是叙事主体」的信号**（编辑侧非外观信号：
   字幕/语音/文字卡）。09-05 的复审已明确指出方向，但当时没有可用的非外观通道。

## 6. 建议

**不建议重开 `_subshot_relocalize`。** 三条理由按硬度排序：

1. **已在 runtime 里测过四片、零收益零退化，且死结是机制性的**（采纳无选择信号），
   不是「调参/换触发条件」能解决的。
2. **oracle 上限只有 +2/139**，其中 1 条（t2r05a）经多模态复审发现是 GT 窄窗对位假象
   ⇒ **真实 oracle 收益 ≈ +1**，远低于本项目 runtime 化门槛（参照：两级切分 +8、事件扩池 +14 才接入）。
3. 把 fallback 升为主路径会**改变导出段数**，而收益上限 +1 ⇒ 风险收益比不成立。

**如果要动，唯一有理论依据的方向是**：「引入编辑侧非外观信号（字幕 OCR / 语音）来选子镜头」。
这是一个**新立项**（不是重开旧线），且需要先回答「字幕 OCR 在我们这条链上成本多少、
能不能稳定给出「这段在讲什么」」。**我不建议现在开**——因为这会是一次比 TopK 大得多的投入，
而当前主线的未结项（mac 包 / 出 r28 / 立项③）都还没动。
