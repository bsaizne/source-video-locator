# 立项 A — 原片镜头检测（scenes.npy）改进 · 2026-10-11

> 状态：**立项提案，待评审，未开码**。触发：用户报"快剪解说导出成片有重合/顺序乱"，
> 多模态读图定性根因 = 镜头检测漏切。B（取材扩宽相对护栏 K=2.5，代码笔 `098021b`、档案笔 `c873e18`）只是
> **绕开扩宽这个放大器**，没修检测本身；本文是治本线的立项。

## 1. 问题与一手证据

- **检测器现状**：`feature_store._build_scene_table` → `engine/segment/segment.detect_shots`，
  作用在 **1fps 的 DINOv2 CLS 特征**上，判据 = 相邻帧余弦距离的**局部 z-score 尖峰**
  （`SCENE_CUT_ABS=0.15` 距离下限、`SCENE_Z_THRESH=1.5` 主判别、`SCENE_MIN_SHOT_S=3.0` 短段并入、
  `SCENE_SMOOTH=1`）。**语义（CLS）边界检测器**。
- **漏切实证**（test2 生产基线批）：`scenes.npy` 把 **3285.00–3323.00 标成一个 38s 镜头**，
  但逐帧看原片该段是 **4 个不同镜头**（球衣人群 → 灌溉喷灌田 → 喷头特写 → 卧室）。
  全片镜头 **中位 8s、均值 13s、35 段 >30s、最宽一段 265s** —— 系统性偏粗。
- **下游代价**（跨 4 片探针 `work/k_sweep_probe.py`，只读）：「完整镜头」扩宽把 1s 短切撑进这些
  假大镜头后，源区间重叠 **Σ=1432.59s**（test3 单片 909s）。B 护栏把它压回 core 底噪 8.00s，
  但**假镜头本身还在**：边界吸附 `snap_clips_to_scenes` 也吃 `scenes.npy`，吸附目标就是错的；
  事件表 `_build_event_table` 从场景表派生，也被污染。

## 2. 根因判断（为什么 CLS 检测器漏这些切）

CLS 余弦是**语义**相似度，不是**镜头边界**信号。人→田野→喷头→卧室在 CLS 空间可能距离不够尖
（局部 z<1.5 或 s<0.15），尤其：解说片画面切换快、单镜头短、且相邻镜头常同为"暖色调电影画面"。
→ **用像素/颜色层面的突变（硬切时相邻帧几乎必然剧变）来定边界，比用 CLS 语义更对题。**

## 3. 目标与非目标

- **目标**：让 `scenes.npy` 的边界召回/精度显著上来（不漏硬切、不过碎），使
  ① 导出「完整镜头」不再把短切撑进含内部硬切的假镜头；② 边界吸附吸到真切点。
- **非目标（护栏）**：**不改 DINOv2 CLS embedding、不 bump `feature_version`**（那是重建全部特征
  + 全量重验的大动作）。只改**派生的场景表检测算法**；相应需要 **scenes/事件表的派生版本位**  bump
  让旧索引重算场景表（不重抽特征）。

## 4. 方案候选（按代价/把握排序）

- **A1（最便宜，先做）离线扫参**：现有 CLS 检测器上扫 `SCENE_CUT_ABS / SCENE_Z_THRESH /
  context_window`，看能否在不引入过碎的前提下抓住 3285-3323 这类漏切。预期**有限**（根因是信号选错，
  不是阈值），但作为基线 + 排除法，半天量级、不重建索引（只在缓存 feats 上跑）。
- **A2（推荐主线）加一路像素/颜色直方图边界**：索引时对**已解码帧**（或补一遍低分辨率解码）算
  相邻帧 HSV/灰度直方图距离，硬切处该距离必然尖峰；与 CLS z-score **融合**（任一尖峰即候选，
  再 NMS/min_shot）。这是治"语义不敏感"的正解。代价：索引期一次额外低分辨率解码（可复用抓帧缓存）。
- **A3（对照）成熟检测器**：接 PySceneDetect 的 content-aware 作金标准/对照臂，量化 A1/A2 的
  边界 F1。是否引入新依赖需评审（打包体积/许可）。
- 三者关系：A1 打底、A2 主改、A3 当尺子。

## 5. 成功判据（必须先有"尺子"）

1. **建标注集**：给 4 片各标一批真镜头边界（逐帧确认，走 GT 同款纪律），作为边界 GT。
   —— 没有这把尺子，"检测变好"无法证伪，禁止开 runtime 改动。
2. **边界质量**：检测边界 vs 边界 GT 的 **recall / precision / F1**（±0.5s 容差），A2 显著 > 现役。
3. **下游不回退**：三指标（`measure_shot_recall` / `measure_four_results`）不降；
   `check_export_plan_invariants` 五条不变式绿；**关掉 B 护栏**时 scene 重叠也应大幅下降
   （证明是检测修好、而非护栏硬压）。
4. **多模态复核**：抽 3285-3323 等已知漏切段，读图确认真被切开且没切错。

## 6. 风险与成本

- **过碎/假切**：像素距离对闪光、叠化、快速运动敏感 → 可能过碎，反伤吸附与卷轴 → 靠 min_shot +
  边界 GT 的 precision 把关。
- **重建索引**：改检测要重算场景表 + 事件表（所有已索引片）；派生版本位 bump 触发重算，但**不重抽
  CLS 特征**（省大头）。索引墙钟增量 = A2 的额外解码。
- **feature_version 边界**：严守"只改派生场景表、不改 embedding"，否则牵动全量重建 + 精度重验。
- **计时须独占设备**（记忆教训）；**单片形状不外推**（A1/A2 结论必须跨 4 片）。

## 7. 与 B / C 的关系

- **B（已 ship，代码笔 `098021b`）**：导出层护栏，立即止血，保留「完整镜头」卖点。A 修好后 B 可保留（多一道
  保险）或按需放宽 K。
- **C（可选）**：把默认「片段宽度」给快剪素材倾向 core，或 UI 提示。是产品选项，不依赖 A。
- **A（本立项）**：唯一治本线，但最贵、需先造边界 GT。

## 8. 建议的第一步（评审通过后）

先做 **A1 离线扫参 + §5.1 边界 GT 标注**（都不动 runtime、不重建索引），拿到"漏切能不能靠调阈值救"
和"有没有尺子"两个结论，再决定是否投 A2 的索引期改动。产出：`FINDINGS_SHOT_DETECTION_A1_<date>.md`。
