# FINDINGS —— 三指标口径审计 (V5): 口径伪影的真实量级 + 非 HIT 案例的三层归因

> **GT 版本**：`ground_truth_v4.json`(2mkv) + `ground_truth_test1|2|3.json`（139 正例 / 9 负例，v4 口径）
> **基线批**：`work/rerun_<case>_perfopt.results.json`（生产两级切分 + 白闪守卫）
> **索引**：`handwritten_vits14_cls_384d@1_l2+scn1+evt1`（1 fps，四片一致）
> **性质**：评估层审计（口径 + 检索天花板）　**runtime 改动**：零（只新增 `mvp/scripts` 三个只读脚本）
> **触发**：`HANDOFF_CUTMATCH_AND_METRIC_AUDIT.md` §3 提出「严格命中口径系统性缺陷（用 GT 编辑段中点代表整段）
> 使 17/22 非 HIT 实为口径伪影 → 过去所有以 117/139 为标尺的对比（A1 −16 / ViT-B −1 / 场景聚合 −6）都带该噪声」。

## 0. 结论（五条）

1. **该假设在 runtime 三指标层不成立**：把判据放宽到「窗内含任意 ≥0.5 s 重叠」，基线只从
   **117 → 118/139**；原片窗加 ±0.5 s 容差仅 +1（`t1r07a`，位于 span 与 GT 窗相差 0.33 s 的边界）。
   ⇒ **口径噪声量级 ≤ +2，而 A1 的差异是 −16**；「必须重跑四片基线才能重估 A1/ViT-B/场景聚合」**不成立**。
2. **真正的口径缺陷只有 2 例（1 例结构性 + 1 例容差边界）**：
   `t1r08c`（GT 编辑窗零宽 `[33.00, 33.00]` → 现行编辑侧判据 `ed_inter > 0` 结构性永远为 0）
   与 `t1r07a`（span 起点越界 0.33 s）。修正后基线 **119/139**。两例均已出图人工确认命中（`work/caliber_v5/`）。
3. **编辑窗 ±0.5 s 是"膨胀"而非"修正"，已拒绝**：它让基线 117→123（+6），但逐例结构核查显示
   **6 例翻转中 5 例的严格编辑侧重叠 = 0.00**——命中由**相邻编辑段**用大跨度场景 span（`[2917-2964]`、
   `[3626-3660]`、`[347-356]`…）认领。⇒ 采用该判据会把"下一个镜头的宽场景 span"算成本案例命中。
4. **三组对照在全部 7 组判据下结论稳健**：A1 TransNetV2 **−16 ~ −17**（膨胀判据下也只回到 −8）；
   ViT-B **−1 ~ +1**（口径内抖动，等价）；场景聚合（仅 2mkv）**−6 / −8** 逐位不变。
   ⇒ 「TN 切分更差」与「换更大基座无增益」**均与口径无关**；同时 ViT-B 的"−1"本身落在噪声量级内，
   应改写为「两基座在该口径下不可区分」。
5. **非 HIT 案例的主因不在特征层，而在定位层**：139 例中
   **口径 2 / 定位层 19 / 特征层 1**（`t2r05a`，GT 窗内最佳帧全片 rank = 77、sim 0.479）。
   定位层 19 例的检索天花板为 **17 例 rank ≤ 3、2 例 rank 5–7**。
   ⚠️ 该天花板用 **GT 引导查询点**（编辑窗内 6 点）测得 = **oracle 口径上界**，不等于可实现收益
   （与 2026-09-05 蒙太奇子镜头方向的 oracle 教训同型）。

## 1. 方法：7 组判据并行评估（零 runtime）

脚本 `mvp/scripts/measure_recall_v5.py`（纯结果文件 + GT，不 import `mvp/src` 定位逻辑）：

| 判据 | 定义 | 性质 |
|---|---|---|
| `S_strict` | 现行口径：编辑侧重叠>0 且（span 落窗 ±2s 内 \| GT 中点在 span 内 \| 覆盖 ≥40%），含联合覆盖回退 | 基线（自检：逐位复现 `measure_shot_recall.evaluate`） |
| `Z_point` | 仅当 GT 编辑窗零宽时改用"点包含"判定 | **合法修复**（公式结构性缺陷） |
| `T_tol05` | 原片窗 ±0.5 s 后再判三选一 | **合法容差**（1 fps 索引粒度） |
| `R_rec` | `Z_point` + `T_tol05` | **推荐辅助口径** |
| `O_overlap` | 追加"原片侧实质重叠 ≥0.5 s 且 ≥50% min(span,GT)" | 宽松上界 |
| `A_any` | 追加"原片侧任意重叠 ≥0.5 s" | 最宽上界 |
| `SE_diag` | 编辑窗 ±0.5 s | **膨胀对照（拒绝）** |

自检：`S_strict` 与既有 `measure_shot_recall.evaluate` 的 `mark` **逐位一致**（四片 139 例），
故本表可直接与历史数字对照。

## 5. 对项目的含义

1. **三指标口径维持 `S_strict` 为主口径**（历史可比），**并列报告 `R_rec`** 作为修正口径
   （基线 119/139），并把 `Z_point` 的零宽修复视为**无争议缺陷修复**。
2. **不建议**采用 `SE_diag`/重叠式宽松判据——会被相邻编辑段的大场景 span 认领（§2.2）。
3. 下一阶段最大的可动杠杆是**定位层（19/139）**，而非特征层（1/139）：
   运行期已有"整段单一查询单元"的稀释机制（5 例 ratio ≥2）与"池/选择"缺口（14 例）。
   ⚠️ 天花板是 oracle 口径，重开该方向前必须先解决**无 GT 的查询点/子镜头选择信号**
   （与 `FINDINGS_SUBSHOT_QUERY.md` 的结论一致）。
4. 「换更大基座」的对比口径应改写为「不可区分」，不再表述为「轻微负向」。
