## 0. 结论（四条，全部本批实测）

1. **抓帧是成本主项，而且卡在「管道 I/O」而不是推理**：实测 ISC 推理 **30.4 fps**（0.0328 s/帧），
   而窗解码抓帧 **7.65 帧/s（0.1308 s/帧）= 推理的 4 倍**。原因 = `_decode_window` 对窗内**每一帧**
   都从 ffmpeg stdout 读一份**原始分辨率 BGR**（test1 1920x960 = 5.53 MB/帧），只为取其中 1/25~1/30。
   ⇒ 抓帧成本 ≈ 管道搬运量，与「要几帧」几乎无关、与「解码多少秒」成正比。
2. **⇒ 最高杠杆 = 让 ffmpeg 只吐需要的帧**（网格扫描用 `-vf fps=1/N`，可选 `-s` 预缩放）。
   粗扫目标本来就是 2s 均匀网格、候选/细化是 1s 网格 ⇒ 管道量可降 **25~60×**，且它同时作用于
   shot_split / patch_refine（续34 实测 grab 占两旋钮段 **77.6%** wall）⇒ 是**全链**收益。
3. **ISC 源片索引化 = 22.4 min/片源（8.4 MB），收益在「同一母片多条成片」复用**：
   实测 test1-om 1s 网格 600s 试建 = grab 78.5s + embed 19.7s；外推整片 8,229 帧 = **22.4 min / 8.4MB**。
   它把「每条成片重扫 ±90s」换成「每部母片建一次表 + 每条成片一次 matmul」，但**建表本身也吃同一条管道**，
   所以先做第 2 条（管道）才能让索引真正便宜（预计建表 22.4 → 6~8 min）。
4. **「宽扫 main-agreement 门」实测不可分（不建议单独上）**：301 个合格段里仅 **15 段（5.0%）**
   被宽扫切换；但真增益行落在主分布**之内**——p20 0.598 / p34 0.674 / t2r06c 0.509 vs 未切换段
   p25 0.678 / 中位 0.771。要保住三条增益必须 θ ≤ 0.70，此时只跳 **67.1%** 且仍误跳 3 段切换；
   θ=0.80 才误跳 0，但只跳 33.2%。⇒ 收益/复杂度比远差于第 2 条。

## 1. 成本单元（本批实测，test1）

| 单元 | 实测 | 口径 |
|---|---|---|
| ISC 单帧推理（含 cv2 预处理，DML） | **0.0328 s/帧 = 30.4 fps** | 600 帧 / 19.7 s |
| 窗解码抓帧（1s 网格、40s 簇） | **0.1308 s/帧 = 7.65 帧/s** | 600 目标 / 78.5 s |
| 原始帧体积 | 2mkv 2.64 MB / test1 5.53 / test2 5.97 / test3 4.61 | 1280x688 · 1920x960 · 1920x1036 · 1920x800 |
| 管道吞吐（推算） | ≈ **676 MB/s**（8 簇 × ~1,200 帧 × 5.53MB / 78.5s） | 与「目标数无关、随解码秒数线性增长」一致 |
| 段级小窗打分（3 ED + 5~7 源帧） | **≈1.17 s/段**（301 段 / 352 s） | `main-score` 探针 |

**关键推论**：宽扫每段要解 + 搬 ±90s（≈4,500 解码帧 × 5.53MB ≈ 25GB）⇒ 按 676MB/s ≈ **37 s/段**；
续45 实测宽扫增量 = +88 min/四片 = **18~24 s/段**（301 段口径）⇒ 同量级且同向。
**因此续47「宽扫大头在 DML 逐帧 embed 而非抓帧」的定性需要更正**：本批实测抓帧单元成本是推理的 4×，
且抓帧量正比于窗口长度而非目标数。

## 2. 杠杆清单（按 收益 × 确定性 / 风险 排序）

### L1（首选·全链）解码管道 I/O：网格抽取 `-vf fps=1/N`（+ 消费者侧 `-s`）
- **现状**：`_decode_window` 逐帧 `read(frame_bytes)`，只为取 1/25~1/30 的帧。
- **改法**：新增网格抓帧路径（`grab_grid(path, t0, step, n)`）：`-ss t0 -copyts -vf fps=1/step`
  （可选 `,scale=512:512` 给 ISC 消费者，`scale=518:518` 给 CLS 消费者）。
- **预期**：管道量 ÷25~60（仅 fps）× 再 ÷9（512² 缩放）⇒ 抓帧 0.131 → **~0.005~0.02 s/帧**；
  宽扫 18~24 s/段 → **~3~6 s/段**；并对 shot_split/patch_refine 同幅生效。
- **风险**：`fps` 滤波选帧规则 ≠ 现契约「首个 pts ≥ t」；**但宽扫/切分帧从不进索引**（不进 `feature_version`），
  只需保证 ISC 决策质量。验证 = ① 抽样与 `grab_frame` 逐字节（或 max|Δpixel|）对比；② 同 t 上 ISC 余弦差；
  ③ 抽样段决策一致 + 四片回归。
- **成本**：半天级；不需要新模型、不改语义版本。

### L2（结构）ISC 源片索引：每部母片建一次 1s 网格 ISC 表
- **一次性**：整片 N 帧（1s 网格）；实测外推 test1 = **22.4 min / 8.4 MB**（L1 落地后预计 6~8 min）。
- **每次**：每段只做「3 ED ISC + 表上 matmul」⇒ 宽扫 **18~24 s/段 → 近似 0**。
- **复用账**：同一母片 N 条成片时，现方案 = 22 min × N；索引 = 建表一次。N=1 持平、N≥2 起每片省 ~22 min。
- **附加收益**：扫描范围从「现主 ±90s」扩到**全片**（有可能覆盖 far 桶 = 续43 登记的两族之一）。
- **风险/验证**：决策变化需四片回归（同 v2 口径）；建表帧的抓取规则须先被 L1 的验证钉死。

### L3（弱·兜底）宽扫 main-agreement 门（用 1 次廉价打分决定是否跳过宽扫）
- **实测**：301 段 15 段被切换（2mkv 4 / test1 0 / test2 3 / test3 8）；`main_score` 分布
  **切换段** min 0.300 · p25 0.398 · 中位 0.509 · p75 0.639 · max 0.791；
  **未切换段** min 0.384 · p25 0.678 · 中位 0.771 · p75 0.825 · max 0.936。
  ⇒ 两族**大幅重叠**（真增益行 0.509/0.598/0.674 落在未切换段主体之下）。
- **阈值扫**：θ=0.60 跳 88.4% 但丢 p34 增益；θ=0.70 跳 67.1%、丢 0 条 MUST_KEEP、误跳 3 段切换；
  θ=0.75 跳 54.2%、误跳 1；θ=0.80 跳 33.2%、误跳 0。
- **裁决建议**：**不单独上**（收益上限 67% 且依赖阈值脆弱性 + 需四片回归），仅作为 L1/L2 之后的兜底。

### L4（未测·便宜）FP16 ONNX
- ISC@512 与 DINOv2 ViT-S 均可导出 FP16 图；DML 上通常 1.3~2×；验证 = 同帧余弦 + 吞吐。
- 与 L1/L2 正交，可叠加；未做任何实测前不下结论。

### 已判负·不再碰（有据）
- 硬解 `-hwaccel`（像素差 1.05 违反冻结帧契约，续47）
- ISC 批量推理（batch1 33.2 fps 最优，续47）
- 索引密度 ÷2（续49 结构账：收益全在一次性 19.1 min，每次定位零节省）
- 宽扫阶梯/提前收工（续48：过门峰≈切换段仅 10%，结构性净亏）

## 3. 建议顺序（把成本打下来的最短路径）

1. **L1 先做**：纯 I/O，零语义版本风险，抽样逐字节 + ISC 余弦即可自证；收益覆盖全链（宽扫 + 切分 + 精排）。
2. **L1 之后再看 L2**：建表成本会被 L1 一起压低，届时「每条成片省 ~22 min」才真正划算；
   并且 L2 顺带提供了「全片扫描」这个能力升级（比省时间更值钱的方向）。
3. **L3 不做**（本批已给出不可分证据）；**L4 可并行做**（独立、便宜）。

## 4. 边界

1. 管道吞吐 676 MB/s 是**推算值**（按 8 簇 × ~1,200 解码帧），未直接测 pipe 字节数。
2. 「宽扫 18~24 s/段」来自续45 的**四片增量口径**（+88 min / 301 段），未单段插桩。
3. `main_score` 用 ON 臂主 span 当「宽扫前的主」近似（两臂切分一致），少量段可能受聚簇路径影响。
4. 未改 GT、未 bump `feature_version`、未翻任何默认值、未 git 提交；**L1 已改 `mvp/src/media/ffmpeg`（见 §5）**。

## 5. L1 落地实测（2026-10-03 同日，续50 补）

**实现**（`mvp/src/media/ffmpeg/ffmpeg_io.py`，零契约破坏）：

- 新增 `grab_grid(path, t0, step, n)`：默认滤镜 = `select='isnan(prev_selected_t)+gte(t-prev_selected_t,STEP)'`，
  配 **`-fps_mode passthrough`**，选帧仍走冻结规则 `first_ge`；`grab_frames` 增加
  `filters / size / match / passthrough` 透传，`size` 非空时自动把 `scale=W:H` 拼进滤镜链。
- **两个反例已留痕**：① `fps=1/N` 滤波会**重定时间轴**（实测帧落到 +0.5s，ISC cos 均值仅 0.78）⇒ 弃用；
  ② 少了 `-fps_mode passthrough` 时 vsync 会**复制帧补 CFR**（5 帧 → 149 帧）⇒ 必带。

**生产形状 A/B**（test1-om，t0=1382.5，180s 窗，2s 网格，91 点 = ISC 宽扫粗扫形态）：

| 模式 | 墙钟 | 加速 | 逐点保真 | ISC cos（对 base） |
|---|---|---|---|---|
| base（现役窗解码） | **27.9 s** | 1.00× | — | — |
| **grid（select 抽取）** | **11.1 s** | **2.51×** | 79/91 **逐字节同帧**；其余 12 点 ≤1 源帧 | min 0.922 / mean **0.997** |
| grid512（grid + scale=512:512） | 10.7 s | 2.61× | 形状不同（预缩放，看 cos） | min 0.921 / mean **0.996** |
| gridfps（对照，fps 滤波） | 10.3 s | 2.70× | 相位整体偏移 | min 0.233 / mean 0.785 ❌ |

**为什么只有 2.5× 而不是预期的 25~60×**（本批新增的第二个关键事实）：

select 只消掉了「管道搬运」（base 27.9 s 里约 20 s = 5,400 帧 × 5.53MB ÷ 676MB/s），
剩下的成本是**纯解码**——同窗 `ffmpeg -f null -` 实测 **8.5 s（21× 实时；顺序解码 26~27× 实时）**，
即 `grid` 的 11.1 s 里 **≈8.5 s 是解码地板**，已经压不下去。
⇒ **L1 把 grab 打到解码地板附近；要继续降本只能减少「被解码的秒数」**，这正是 L2（源片索引 = 全片一次
顺序解码）与硬解（对扫描路径做 cos A/B，不照搬旧结论）的位置。

**门禁**：后端全套 `unittest discover -s mvp/tests` = **505 OK (skipped=2)**（95.8 s，新增 6 项 grab_grid/filters 单测）。
**接线（同日第二批）**：宽扫粗扫已走 `grab_grid`（旋钮 `pipeline.grab_grid_decode`，**默认 False**）；test1 整条 locate A/B 运行中。**尚未接线**：其它抓帧点（见 §5.1 实测结论）。
### 5.1 另两个抓帧点的实测结论（同日）——不接线

| 形状（实测） | base → grid | 保真（ISC cos） | 结论 |
|---|---|---|---|
| shot_split（3s 段 @4.8fps，15 点） | 0.5s → 0.2s（2.10×） | **min 0.335** / mean 0.942 ❌ | **不接线**：亚秒步长下 select 逐步累积漂移 |
| patch_refine 小窗（1s / 0.25s 步长，5 点） | 1.3s → 1.2s（1.08×） | min 1.000 / mean 1.000 ✅ | **不值得接线**：绝对收益 ≈0.1s/次 |

**为什么亚秒级网格不可用（机制留痕）**：select 的判据是「距上一选中帧 ≥ step」，当 step 不是源帧长
的整数倍时，每步都会向上取整到下一源帧 ⇒ **误差逐步累积**（test1-ed 0.208s 步长在 15 点后已错位到
整格）。宽扫粗扫的 2s 步长约为源帧长整数倍 ⇒ 漂移有界（实测 79/91 逐字节同帧、其余 ≤1 源帧）。
⇒ `FFmpegIO.MIN_GRID_STEP_S = 1.0`：**step < 1s 一律回退旧路径**（护栏 + 单测锁定）。
⇒ 结论：**网格抽取只对「宽扫粗扫」这一个形状有意义**（180s 窗 × 91 点），其它抓帧点保持旧路径。
### 5.2 漂移修复（同日第三批）：select 判据改「锚定簇起点的绝对窗口」

**问题**：初版判据 `gte(t-prev_selected_t, STEP)`（距上一选中帧 ≥ step）在 step 不是源帧长整数倍时
**每步都可能多走一帧并累积**——实测 test1-om 1s 网格 600 点只有 **121/600** 逐字节同帧，
test1-ed 0.208s 步长 15 点只有 3/15（ISC cos 最低 0.335）。

**修复**：`FFmpegIO._grid_select_expr(lo, step)` = 选中每个 `[lo+k*step, lo+(k+1)*step)` 窗口内的**第一帧**
（`filters` 参数支持 callable，按每个解码簇的起点 `lo` 生成表达式）⇒ 窗口由绝对时间决定，**误差不累积**。

**验证（同一批形状，修复后）**：

| 形状 | base | grid | 加速 | 逐字节同帧 |
|---|---|---|---|---|
| test1-om 300s @1s（300 点） | 60.2 s | 25.5 s | **2.36×** | **300/300** ✅ |
| test1-om 180s @2s（90 点 = 宽扫粗扫） | 35.8 s | 13.7 s | **2.61×** | **90/90** ✅ |
| test1-ed 3s @1s | 0.4 s | 0.3 s | 1.33× | 3/3 ✅ |
| test1-om 600s @1s（**L2 建表形状**） | 123.6 s | 49.4 s | **2.50×** | 121/600（旧判据）→ 修复后见上 |

⇒ 修复后网格路径在**整数秒网格上逐字节等价**（升级为「零语义」级别），亚秒步长仍由
`MIN_GRID_STEP_S = 1.0` 护栏回退旧路径。

### 5.4 四片 A/B 抓到真缺陷：生产相位网格偶发「整格跳位」⇒ 安全网（续51）

- **现象**：test1 **0 差异**（PASS）；**test2 3/67 段落点差**（LOW 置信，位移 23~26s）；**2mkv 段数 83→84**。
- **逐项证伪**：① 窗解码在 1.mp4/test1-ed 上 **0/120、0/60 不一致**；② test2-om/2.mkv/test3-om 各 91 点
  **0 不同帧**；③ 切分同配置两遍一致、开关旋钮也一致（69=69=69）⇒ 三条全部排除。
- **真因（机制）**：生产网格 `round(wlo + i*2, 3)` 步长有 0.001s 级抖动，而 select 窗口按**统一 step** 生成；
  窗口起点随时间缓慢漂到目标之前 ⇒ 个别目标落到**下一格（+2s）**的帧（t0=1285.533 的 91 点里 **6 个**）
  ⇒ 粗扫分数变化 ⇒ 低置信段 argmax 翻转。
- **修复**：`_decode_window(max_pts_lag=)` 安全网——分配帧 pts 晚于目标超过 `min(step, 0.5)` 即**拒绝**，
  交回 `grab_frame` 精确抓取；`grab_grid*` 默认传该阈值。
- **验证**：4 组生产相位网格 **0 不同帧**，抖动相位触发 **6 次**精确回退（≈6/91 点，成本可忽略）。
- **协议修正**：归档批 `v2_*` **不能**当单变量 A/B 的 off 臂——2mkv 的段数差与旋钮无关（切分对旋钮不敏感），
  属跨代际差异 ⇒ 2mkv 走**双新臂**（`--force`）；test2/test3 用 `--force-on` 重跑 on 臂。
- **流程教训（自查）**：A/B 脚本首版「产物存在即复用」在代码变更后会**静默复用旧 on 产物**（本批真的踩了：
  test2 首轮重跑其实是旧产物比较）⇒ 新增 `--force-on`，代码改动后必须显式重跑 on 臂。
