## 一、口径(与原脚本一致)

- 查询帧 = 编辑片 `qt±0.4s` 三帧,**逐帧 L2 归一化后取均值再归一化**(与原 `embed_batch` 完全一致);
- 干扰窗 = ViT-S **全片索引** top-40 相似帧(排除真值窗 ±10 s)按 gap 5 s 聚区取前 2 区、±10 s 扩边,再插入人工窗(兄弟机位 / 已知错位);
- ViT-S 侧用**全片索引缓存**(2.mkv 7668 帧 @1fps L2 CLS 384d;test3 10177 帧),ViT-B 侧对「真值窗 ±1 s ∪ 干扰窗」**局部嵌入**(batch=4);
- 指标:`true_max − wrong_max = margin`,并记录 argmax 落点;patch 通道 = research_phase21 **V3 定义**(query patch 对候选帧 patch 最大余弦的 top-100 均值),每窗候选帧 thin 到 12 帧(与原 probe2 一致);
- 设备:**CPU 前向**(ViT-B 无 DML/ONNX 资产、本机 torch 为 `2.13.0+cpu`;本探针无 GPU 路径)—— 与 2026-08-30 原口径一致,GPU 优先约定(见 `.agent/DECISIONS.md`)在此不适用并已留痕。

## 六、净结论

1. **「换更大基座无效」的原证据不成立**:最强反证 p08b(−0.138→−0.281)是 GT 污染假象(修正后 S −0.014 / B −0.017);
2. **但实践结论在修正数据上复现**:两基座在失败族(兄弟机位)**都不可分**,整体**无一致方向**(CLS 5:4 / patch 6:3,幅度 ≤0.08);
3. **「p26 类硬混淆」不再存在**:正确位置 1768.2-1770.05 在 ViT-S 全片索引 **rank 1**(旧的"特征上限"叙事源于 GT 标错);
4. **维持「不建议 bump feature_version 全量重建」**(收益无据 + 768d 存储/ONNX 资产/全量回归成本翻倍);
5. 仍需的"唯一未被本探针覆盖"的问题:ViT-B 的**全片索引**行为(本探针 ViT-B 侧为局部窗口嵌入,干扰窗由 ViT-S 选出)
   —— 若要产品级定论,需导出 ViT-B ONNX + 全量重建索引 + 四片 runtime 回归(成本远高于本探针,未做)。

## 七、边界(诚实声明)

- ViT-B 侧是**局部窗口嵌入**(干扰窗由 ViT-S 全索引 top-40 选出),不是全片索引 → 本探针只能回答「**判别/排序是否更好**」,
  不能回答「ViT-B 能否把 CLS 漏掉的正确区**召进池**」;本次 9 探针中 ViT-S 真值帧全片 rank ≤6,故对该问题本就无迫切性;
- 干扰集是"ViT-S 选出的最强混淆区 + 人工窗",覆盖保守但非穷尽;
- 1 fps 采样、518×518、CPU 前向(与生产前向同口径,但生产检索用 DirectML ONNX);
- 未测 DINOv2-L/H(趋势外推无依据)与 DINOv3(许可另议);
- 探针集只覆盖 2.mkv 与 test3(test1/test2/test4 未纳入;test4 数据无效);
- 单探针耗时 ~2-3 min(CPU),9 探针 1294 s;重跑成本可控(脚本支持 `--only`)。
