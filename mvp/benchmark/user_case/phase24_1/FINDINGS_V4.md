## 一、口径

与原脚本 `research_phase24_1.py` **逐条一致**,仅换真值窗/兄弟窗(见下表):

- 候选集 = CLS top-40 ∪ 真值窗 ∪ 兄弟窗(逐帧);
- 每帧对:patch 互近邻匹配(`mutual_nn`)→ `cv2.estimateAffinePartial2D`(宽松仿射 RANSAC 5px)内点率 **INL**
  + `cv2.findHomography`(单应 RANSAC 5px)内点率 **HOM**;
- 名次定义与原脚本一致:排除兄弟窗帧后,按该指标降序,真值窗中**最好的一帧**的名次(= rank,越小越好);
- 探针②:查询(编辑)窗 ±1 s 抽 8 帧 → 帧差能量序列 → 皮尔逊相关 + L2;
- 探针③:分块余弦,sim ≥ 0.60 且 |Δt| ≥ 2 s 且跨场景 = 硬负例;锚点场景内跨场景同貌实例数;
- 设备:CPU torch(ViT-S/14 冻结 backbone),与生产前向同口径;探针③纯 numpy。

### 裁决

1. **原证伪证据作废**:原 FINDINGS ① 表格里「p08b:1048 HOM 0.488 vs 1109 HOM 0.752 → ❌ 兄弟压倒」——
   1109 本就是**真值**(p08 的正确位置),而 1048-1050 是作废的错误 GT 区 → 该结论**方向性错误**;
   p26 的「几何 rank 2 假阳性」同样来自标错窗口(修正后 rank 1)。
2. **原记录与结论自相矛盾(p08)**:原存档 `phase24_1_probe_results.json` 的 p08 记载
   `GEOM_HOMOG = [1, 41]`(真值帧 HOM 内点率已是第 1),但 FINDINGS 文字只拿 1108(HOM 0.331)与 1048(0.506)对比得出「兄弟反超」——
   **文档未使用自己的名次数据**;本次维持同口径复算得到同一结论(HOM rank 1)。
3. **但不足以立项为 runtime 重排信号**(三条硬理由):
   (a) **度量互相矛盾**:同一批互近邻对应关系下,HOM 判真值胜(0.849 vs 0.506),INL 判兄弟胜(0.407 vs 0.411);
   (b) **帧对齐极端敏感**:真值窗内 1108 HOM 0.331 → 1109 HOM 0.849(1 s 跳变 0.52),INL 0.286 → 0.407;
   (c) **样本仅 2 例且同一场戏**(p08/p08b 是同一编辑段两个查询点、同一对机位),不足以支撑泛化判断;
   另有已知偏置:兄弟帧互近邻对数明显偏多(267-329 vs 66-78),内点率归一化后仍不中性。
4. 原 FINDINGS 的**理论归因(刚性场景不同机位仍满足单应)在数据上不再成立**——真值帧单应内点率显著高于兄弟帧。
   该理论段需一并标注作废(见 §五)。

## 六、净结论

1. **探针①的旧结论(几何证伪)不成立**:两条核心证据(p08b 兄弟压倒、p26 几何假阳性)都是 GT 污染产物;
   修正后 **HOM 口径反而把真值帧排到 rank 1**(4/4 硬例),但 **INL 口径相反**且帧间跳变极大 →
   「几何一致性 **既不能说是已证伪,也不能说已可用**」,需专门复验(§八)。
2. **探针②、③结论不变**(运动签名方法学不成立;硬负例不缺、缺的是可分信号)。
3. **失败族收窄**:修正 GT 后 2.mkv 侧仅 **兄弟机位族(p08/p08b,CLS rank 5-6)** 仍为真实失败案例;
   p26(夜读)不再是失败案例。
4. 本重跑**未改 runtime、未 bump feature_version**;四片三指标基线不受影响。

## 七、边界(诚实声明)

- 几何探针的候选池是 **CLS top-40 ∪ 真值 ∪ 兄弟**(与原脚本同口径),不是全索引;
  真值帧的 HOM rank 1 只说明「在该池内、排除兄弟窗帧后最好」,不等于全片可操作排序;
- 只有 p08/p08b 构成「同场戏兄弟机位」对照(同一对机位、两个查询点),其余 4 例是易例/重复镜头/修正后的易例,
  不是对判别力的独立检验;
- RANSAC 未显式固定随机性,单次结果可能有小幅波动;本脚本未做重复采样稳定性检验(原脚本亦然);
- 探针②的两段窗口比对仍是单尺度(±1 s / 8 点),未做 DTW 等时间对齐——这是它被证伪的原因,本次不修正;
- 探针③的锚点场景由 scenes.npy(scn1)给出,场景表本身是索引派生缓存。
