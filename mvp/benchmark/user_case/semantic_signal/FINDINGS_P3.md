→ 快剪解说片的编辑镜头序列与原片时间轴**非 1:1 对应**(与 Phase 24-1 探针②一致)。

### P3b p08 序列匹配 = ❌ 证伪(不升反降,兄弟被推到 top-1)

### P3c p26 对照 = ❌ 证伪(答案被拉向错误区域)

| 口径 | 真值场景295 |

**远离真值 2809**。

## 归因(为什么序列上下文在此案例族上结构性不可行)

1. **编辑上下文自身就混着兄弟内容**:p08 编辑段后面的相邻镜头 **p09 内容恰来自原片 1048-1082
   = 兄弟机位 p38(1048-1050)所在区域**。序列匹配把三段分数叠加,兄弟区域同时被
   p09(直接内容)+p08(兄弟画面)命中 → 分数最高。**上下文不是独立证据源,它自己就是兄弟内容。**
2. **同一场对话戏的镜头在原片里集中在同一时间窗(1010-1154)**:兄弟机位和真值机位、
   以及它们的前后镜头,全部落在同一个原片连续窗口内。不存在"只在 1108 出现的唯一上下文"——
   编辑片把这场戏切碎重排,序列上下文在原片侧找不到可区分兄弟的证据。
3. **p26 是编辑重排的极端形态**:p26 编辑相邻镜头(p40/p41)原片位置在 1772-1780,
   与真值 2809 相隔 1000s+——上下文把答案往错误方向拉。

## 净结论

- **第六路信号(镜头序列上下文)= 证伪**,特征上限正式封顶:
  - p08(兄弟机位):序列匹配兄弟 top-1、真值 44→61,不升反降
  - p26:真值 17→35,答案被拉向编辑上下文所在区域(1772-1907)
- **回答用户三个前置问题**:
  1. **p08 查询片段是否含完整镜头边界?** → **否**。编辑段 [12.6,14.3] 只覆盖原片场景134
     (1106-1121) 内部 1108-1110 两秒(15s 场景的 2/15),不含完整边界。但编辑侧 GT 边界
     提供了 p07/p08/p09 三个完整查询镜头,所以"查询有前后镜头"成立;失败不在此。
  2. **现有 pipeline 有无镜头边界可复用?** → 编辑侧 1.mp4 索引 scenes.npy 仅 2 个粗场景
     (0-90/90-126),无细边界;但 GT v3 编辑段边界可当查询镜头用(本探针即用)。
     原片侧 scenes.npy(699 场景)完整可用。
  3. **p26 上下文是否也有序列差异?** → **是,更极端**:编辑相邻镜头原片位置 1772-1780,
     真值 2809 差 1000s+,上下文把答案拉向 1772-1907。
- **根因不在"缺上下文",而在"编辑片把同一场戏切碎重排 + 兄弟内容混入编辑上下文"**——
  快剪解说片的前提(编辑序列≈原片序列)不成立,序列上下文无法成为独立证据源。
- 零 runtime 改动;三指标 39/41 不受影响。
