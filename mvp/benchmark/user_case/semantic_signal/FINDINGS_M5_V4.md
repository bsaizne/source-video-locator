## 三、裁决

1. **M5 的核心卖点作废**:原结论「patch 对兄弟机位选对实例有效(**p08b 32→2**)」的 32 与 2 都建立在
   **p38 旧错误 GT 区(1048-1050)**上。修正后该案例的正确位置(1108.15-1109.1)在 CLS 全索引排 **5**、
   在池内 CLS 排 5、patch 排 **9** → **既不是"CLS 漏掉",patch 也没有救回**,方向性结论反转。
2. **p08 维持**(CLS 6 → patch 5):这是 M5 里唯一真实存在的 patch 重排名次改善,幅度 1 名,且仍在池内第 5
   —— 与 runtime 已落地的 patch 重排(patch v2)一致,无新增空间。
3. **p26 不再是"CLS 漏、patch 也捞不回"的案例**:修正 GT 后正确区是 2.mkv 全索引 **第 1**
   (与 feature_upgrade_v4 / phase24_1_v4 的结论一致)。
4. **与 M6 v4 一致**:M6 在 v4 GT 全量 39 条上重算得 **RESCUE 0/39、CLS 池内 39/39**;
   本次 M5 在同一口径下逐案复核得到相同图景 → **「patch 作为独立召回通道」方向关闭(有据,修正口径)**,
   但关闭理由从"M5 只救回 1 例"改为"**原 M5 的所有正面证据都来自 GT 污染;真实图景是正确区几乎总在 CLS 池内,
   patch 的贡献仅限于池内小幅重排(已在 runtime)**"。
5. 原 FINDINGS 中「M6 的 p38 行不作数」类互相矛盾("M5 的 p08b 32→2 在 M6 p38 不复现"——同一目标区)现在有统一解释:
   两者都在测**同一个作废的错误 GT 区**,查询帧不同才出现差异。

## 四、边界(诚实声明)

- 池内 rank 只在「CLS top-200 ∪ 均匀采样 ∪ 真值/干扰窗」这个混合池内可比,不等于全索引名次(CLS 全索引 rank 已单列);
- patch 打分使用**研究侧 DML ONNX 双输出资产**(ViT-S,与生产 index 同源但为临时导出,数值校验 cos≈1.0);
- 未做 patch 池规模敏感性分析(200/250 采样预算固定,与原脚本一致);
- t3r12 的干扰窗(481-488)是用户 09-02 修正后保留的"另一实例"口径;若该窗不是同一内容的另一实例,只会让 t3r12 的结论更宽松(不影响"无召回信号"的判定);
- 本次未重跑 M6(已于 v4 GT 全量重算 0/39),两实验口径不同(全量 GT vs 6 案例池内),不互相替代。

## 五、净结论

1. **patch 召回层无信号(修正口径坐实)**:v4 下 5 个案例中 2 个"有改善"里,1 个是池内 1 名(易例 p01)、1 个是 CLS 6→5(p08 持平);
   原唯一的强证据(p08b)反转;
2. **兄弟机位族(p08/p08b)在召回层面可用**:CLS 全索引 rank 5-6(进池),问题在**池内排序/定位**而非召回
   —— 这进一步支持「失败族 = 判别力/排序问题」而非「检索缺口」;
3. runtime **无需**为 patch 召回做任何改动(现状即 patch 重排,收益已在 117/139 基线内)。
