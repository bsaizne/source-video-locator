## 探针设计

P2 目标是裁决方向 A(场景实例身份建模)的端到端价值, 分两步:

- **P2a 归并规则**: 原片场景表(scenes + scene_feats)按「**时序近邻 + 指纹联合聚类**」聚合为事件单元:
  边判据 = 场景中心时间差 ≤ T_gap AND 指纹余弦 ≥ S_sim → 连通分量。
  网格扫描 T_gap ∈ {30, 60, 120}s × S_sim ∈ {0.55, 0.60, 0.65, 0.70}(12 参数)覆盖三族。
- **P2b 端到端排序**: 编辑段查询(编辑侧索引 CLS 帧特征均值, L2) → 事件单元代表(单元内场景指纹 L2 均值),
  排序正确事件单元, 并对照三档基线:**帧级**(查询 vs 原片全帧) / **场景级**(查询 vs 原片全场景指纹) / **事件级**(查询 vs 归并后事件单元)。

探针案例:兄弟机位(p08 场景134 + p38 场景128, GT 双真) / 重复镜头(t3-r12 正确[43,44,45] vs 干扰[42,46,47,48]) /
同质场景(test4 [353,354,355] vs [352,356-359], 对照组) / 易例回归(p01/p04/p17) / 特征上限参考(p26)。

## 净结论

1. **方向 A 对兄弟机位族 = ✅ 事件级端到端 top-1(核心正结果)**: P1a 的「信号存在但不唯一(rank 6/11)」
   在加入**时序近邻约束**后不再成立——兄弟机位被归并为单一事件身份, 编辑段查询(对话段 12.5-14.3s)
   直接命中事件 top-1(T_gap=120 稳健, 3 档 S_sim 全部 top-1)。**这正面回答了 P1a 暴露的归并粒度问题:
   归并规则 = 时序近邻 + 指纹联合, 而非纯指纹聚类。**
2. **方向 A 对重复镜头族 = ✅ 保持 top-1**: 与 P1b 结论一致。事件级排序正确(正确实例在事件单元代表中占主导),
   但归并规则**不精确**(时序近邻把相邻干扰 42/46 拉入同一单元)——事件级排序正确 ≠ 单元纯度高。
3. **方向 A 对同质场景族 = ❌ 证伪确认**: 归并规则无法把 test4 正确实例聚成干净单元, 干扰大量混入。
4. **易例零回退**(p01 全档 top-1); p04/p17 的「场景级排名差」是**场景指纹均值稀释伪影**(场景内含多内容时
   均值指纹不代表查询内容), 帧级排名(148/10)正常, 非 runtime 回退——真实 runtime 走帧级检索, 不受此影响。
5. **p26 事件级意外到 2/129, 谨慎解读**: 事件聚合恰把夜读场景拉近, 但该案例 runtime 受检索候选质量限制,
   不构成「特征上限已解决」证据。

**净判断**: 方向 A 的事件归并 + 事件级排序在**研究侧**证明:
- 兄弟机位族: 双真歧义(两个机位各自 rank 6/11) → 单一事件身份 top-1 ✅
- 重复镜头族: 事件级 top-1 保持(正确实例主导) ✅
- 同质场景族: 无效 ❌(与 P1b 一致)

与用户拍板时的预期(**仅重复镜头族 + 部分兄弟机位族**)一致, 兄弟机位族甚至超预期(事件级 top-1)。

## 诚实边界

1. **P2b 三档排名的口径**: frame_level 与 runtime 最接近(帧级检索); scene_level/event_level 为聚合代理指标,
   受「场景指纹均值稀释」影响(p04/p17 表现差即此故, 不代表 runtime 帧级表现)。
2. **编辑侧查询特征**: 1.mp4 索引为 0.5fps(63 帧)、test3-ed 为 1fps(156 帧), 编辑段查询为窗内帧均值,
   短段(如 p04 的 3.5-6.0s)仅覆盖 1-2 帧, 查询代表性有限。
3. **p26 事件级 top-2 为代理结果**, 不宣称特征上限已解决。
4. **事件归并的 runtime 价值未经评估**: 本研究侧证明事件级排序能正确归位, 但 runtime 接入(索引侧事件表
   + 查询先到事件再细化 + UI 事件标识)是独立的实现阶段, 本探针不裁决其工程收益。
5. 零 runtime 改动; `measure_shot_recall.py` 三指标(39/41)不受影响, 未复测(研究侧无触碰)。
