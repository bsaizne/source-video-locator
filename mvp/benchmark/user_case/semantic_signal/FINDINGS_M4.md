## 探针设计

同一编辑段查询(8fps 三帧均值 CLS),在「原片 1fps 稀疏索引」vs「原片 8fps 密帧索引」的
候选池(正确窗∪干扰窗)上对比:**正确窗 best_rank / top5 命中 / margin(correct_max_sim − dist_max_sim)**。

## 结果 = 8fps 密帧对判别力提升几乎为零,且 p26 变差

| 案例 | 指标 | 1fps 稀疏 | 8fps 密帧 | 判断 |
|---|---|---|---|---|
| **p08 兄弟机位** | best_rank / top5 / margin | 1 / 2 / **+0.393** | 1 / **5** / +0.365 | ⚠️ top5 命中改善(2→5),但 rank/margin 无实质提升 |
| **p26 夜读** | best_rank / top5 / margin | **12** / 0 / **−0.280** | **43** / 0 / −0.247 | ❌ 密帧反而更差(best_rank 12→43, 候选池稀释) |
| **t3r12 重复** | best_rank / top5 / margin | 1 / 5 / +0.561 | 1 / 5 / +0.560 | ➖ 完全持平 |
| **t4r01 同质** | best_rank / top5 / margin | 1 / 5 / +0.146 | 1 / 5 / +0.103 | ➖ 持平(margin 略降) |

## 关键归因

1. **索引密度解决的是「候选池里正确帧的数量」,不是「正确 vs 干扰的可分性」**:
   - p08/t3r12/t4r01 在 1fps 下**本来就是 best_rank=1**(不难)——8fps 只是让 top5 内正确帧更多,
     不改变排序结论;
   - **p26 是唯一真正的难例**(干扰 dist_max_sim 0.876 反超正确 0.596, margin 为负)——8fps 让
     候选池从 1057→8448 帧,**正确帧被稀释, best_rank 12→43 反而恶化**。
2. **8fps 没有把任何负 margin 变正**。失败族的分隔瓶颈是「正确实例 vs 干扰实例在特征空间几乎
   同分」,加帧只是把同分内容复制更多份,**不改变相对排序**。
3. **结论与用户直觉相反(但被数据支持)**:「全片按帧解析效果更好」——**在判别层面不成立**。
   30fps 全帧解析只会让存储/索引/检索成本 ×30,对失败族无判别增益(p26 甚至更差)。

## 难例(p26)结合多模态辅助判别 = 既有证据已覆盖且证伪

用户指示「遇到这种难比较的请结合多模态进行辅助判别」。M4 的难例 p26(干扰反超正确、margin 负)
**正是 M1/M2/M3 已完整测过的靶心**:
- **M1b VLM 事件级判定**(查询帧 vs 候选帧):p26 真值 0/3、干扰夜阳台 3/3 —— **VLM 反向选错,比 CLS 更糟**;
- **M3 CLIP 跨模态字幕索引**:p26 字幕「她用望远镜看 Levi」真值 3/3、干扰 1/3 —— 字幕有弱方向,但 CLIP 索引无判别力(Δ<0.003);
- **M2 字幕召回**:p26 真值窗 3/3 EVENT YES —— 字幕语义是 p26 上唯一的弱正信号,但不可规模化。

**诚实结论**:对 p26 这类「干扰相似度反超正确」的难例,多模态辅助判别已在三个独立形态(M1 判定/
M2 召回/M3 索引)下测过,**无一个能可靠地把正确实例从干扰中分离**(VLM 甚至反向)。若未来仍要
「难例多模态辅助」,可行方向只剩:**字幕语义作为弱加权召回通道**(M2 的 3/3 是唯一正向),但需
更多案例验证强度——这是 M3 已证「无法索引化」的形态,收益有限。

## 净结论

1. **索引侧密度(8fps)= 对失败族判别力几乎零增益, p26 反而恶化**。30fps 全片解析的成本(×30)
   换不来判别提升 → **不支持「全片按帧解析」立项**。这与查询侧 Phase 14C 结论现在**双向闭合**。
2. **真正瓶颈 = 特征空间可分性, 不是采样密度**。p26 的干扰在特征空间比正确更近(0.876>0.596),
   这是 CLS 特征本身的混叠,任何帧率都救不了。
3. **难例多模态辅助**:p26 已在 M1/M2/M3 三形态测过,无可靠判别力(VLM 反向、CLIP 无判别、
   字幕弱且不可索引)。维持「特征上限=已知局限」。
4. 零 runtime 改动;三指标 39/41 不受影响。

## 交接

- **索引侧密度方向 = 关闭(有据)**:8fps 实测零增益 + p26 恶化 + 双向闭合(查询侧+索引侧)。
  同类软件 30fps 全片解析是它们的模型/硬件组合(轻量模型或更强 GPU),不适用于我们的判别瓶颈。
- **M1-M4 证据链全貌**:判定(M1)/召回-M2/索引(M3)/密度(M4) 四路全部无解 → 失败族维持特征上限。

  ——若未来做任何 DML 批量推理,用 batch=1 而非 batch=8(现 config 默认 8,可考虑改)。
