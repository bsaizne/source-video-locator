# FINDINGS —— 低信息帧降权 + 段首尾边界帧剥离 探针（2026-09-05 用户方案 1）

> 用户方案（针对 n01/n02「前段模糊/未确定内容 → 误匹配到源片」）:
>   ① 低信息帧降权: 模糊/低对比/无主体帧剔除出匹配（避免泛化特征偶然命中源片）;
>   ② 段首尾边界帧剥离: 剥离过渡帧, 只取段核心帧参与匹配。
> 实现(研究探针, 零 runtime 改动): mvp/scripts/rerun_lowinfo_strip.py 子类化
> SourceLocatorService 覆盖 _segment_twopass_flash, 复用生产两级切分+白闪守卫逻辑,

> ② 段首尾各剥 1 帧(段帧数足够才剥)。GPU 确认: DirectMLBackend/amd。

## 四、失败机制（证据）

1. **误配由剩余正常帧驱动**: n01/n02 删 11/17 帧后, 保留的 6 帧正常帧仍把主 span
   定位到 1692-1694 / 1746-1748（与未降权前完全一致）——低信息帧本就不贡献证据,
   剔除它们不改变「正常帧内容相似 → 误配」的机制。
2. **n03/t3r15 无低信息帧**: 降权无从触发（n03 contrast 全片 85% 分位 = 正常清晰帧,
   t3r15 edge 54% = 正常纹理）, 原样 FP——与摸底预期一致。
3. **副作用**: 段首尾剥离会削掉合法证据（p28 HIT→part）, 严格回退。

## 五、结论

- **不推荐进 runtime**（有据）: 负例零改善 + 严格 -1。低信息帧降权/边界剥离
  针对的是「低信息帧偶然命中」的表象, 而 n01/n02/n03/t3r15 的误配根因是
  **正常内容帧的 CLS 内容相似混叠**——与研究侧 M1-M8「外观层无法区分身份」结论
  一致; 这 4 个负例属于特征上限, 非低信息问题。
- 若未来要救这类负例, 方向仍是「非外观第二信号」（研究侧已闭环, 需另立项）,
  而非像素质量预处理。
