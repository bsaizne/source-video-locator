# 失败分类法（A/B/C/D）—— 基于 M6 全量 GT 数据的固化（2026-09-01）
> ⚠️ **test4 数据错误(2026-09-01):** test4-ed.mp4 与 test4-om.mkv 为两部不同电影(81s竖屏 vs 71min横屏), 本文件中依赖 test4/t4r01 的结论全部作废(逻辑剔除, 详见 datasets/real/test4-INVALID.md)。

> 目的：把「这个镜头算法没找到」拆成四类可诊断的问题，让每次实验明确「该换特征 / 该改排序 / 该改时序 / 该改边界」。
> 数据源：`work/patch_recall_gt_results.json`（M6，41 条 GT 正例，CLS 全索引 best_rank + patch 混合池 best_rank）。
> 口径：候选池线 = runtime 检索 `retrieval_top_k=20`（CLS best_rank ≤ 20 视为「进池」）。

## 分类法定义

| 类别 | 含义 | 诊断指向 |
|---|---|---|
| **A. Feature Recall Failure** | GT 根本没进候选池（CLS rank>20） | 换特征 / 加召回通道 |
| **B. Reranking Failure** | GT 进池了，但被错误候选压下去 | 改排序（重排） |
| **C. Temporal Failure** | GT 已正确，但时序层切掉/改错 | 改时序层 |
| **D. Boundary Failure** | 找到了，但时间边界不准确 | 改 finloc/边界 |

## 关键结论

1. **失败族是「召回失败」与「区分度失败」的混合，不是单一问题**：
   - p38/p24/p41 等 = 真召回失败（GT 不在 Top-K，换特征/加通道）；
   - p26/test4 型 = 区分度失败（GT 在池附近或池内，但干扰在特征空间更近/全片无区分度）——这类即使进池也会被压下去；
   - 两者需要的特征升级方向不完全一样。
2. **M6 证明 CLS 召回在 2.mkv 上 31/41 都进池**——「大量 GT 进不了池」的假设在 2.mkv 上不成立；真正的召回失败只有 10/41，其中 patch 只救回 1 条（p13）。
3. **C（Temporal）/ D（Boundary）本次未直接测**：M6 是召回层实验；C/D 是否在 39/41 基线的 2 个 MISS 中占份，需另立探针（对照「GT 正确但时序层切掉」的 case）。
