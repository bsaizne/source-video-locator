## 3. ⭐ 核心读数（读这一节就够）

### 3.2 现有判据的量化后果（四片 139 条，`work/scn4_*.results.json`）

## 4. 下一步（已授权"开始下一步"，就是它）

**镜头级对齐判据**：用现役真索引里的 `scenes.npy`，把每条 GT 段落窗映射成"它覆盖哪些镜头"，
然后按**我方 span 所在镜头与 GT 窗的集合关系**分三档：

| 档 | 定义 | 含义 |
|---|---|---|
| **IN** | 我方 span 所在镜头**完全落在** GT 窗内 | 我们对（GT 只是更宽），不计边界误差 |
| **PART** | 我方 span 所在镜头与 GT 窗**部分重叠** | 边界真有问题（跨了镜头界） |
| **OUT** | 完全在 GT 窗外 | 真 MISS，这才是要攻的 |

判据产物 = 139 条的 IN/PART/OUT 分布 + 按片分层 + 与现役三指标的对照（**看三指标掩盖了多少 OUT**）。
**零重跑、零改码、不重标 GT。** 真索引在 `%LOCALAPPDATA%\SourceVideoLocator\index\`
（`test1-om__5d4fdc2b.idx` / `test2-om__35b9a58f.idx` / `test3-om__074e2dcc.idx` / `2__4c6d4ab2.idx`，四片都有）。

## 7. 我本轮犯的 8 个错（FINDINGS §11 全文，最重的三条摘这里）

1. ⚠️ **多模态复核是用户开口要求才做的，不是我自己做的** —— 与续76/续77 **同一个病**。
   **纪律：结论形如"好/坏/准/不准"、或要据此提解释/优先级/立项建议时，落档前必须先读图，不等被问。**
2. **把"粒度不匹配"说成"GT 标注噪声"，并据此提议一项重标 GT 的大工程** —— 读图即破。
   「数据有噪声 / 某处有缺陷」这类**甩锅式解释最省事也最容易免检**。
3. **复核选样选错**：声称"从 1:1 干净子集挑两条"，实际挑的行比值 0.30/0.32 根本不在子集里。
   ⇒ 选样脚本要**打印判据实读值自证**。
（另 5 条：口头断言撑宽未验 / 拿单行量复合 GT / 两例判 VSC 无用 / 夹具静默掉 GPU / within 代理写错。）

## 8. 环境坑（本轮新增 4 条，都会咬人）

- **改 `SVL_DATA_DIR` 会静默丢掉 DML/patch/ISC 三份资产 ⇒ 后端回落 CPU 且不报错**（232.9s vs 31.4s = 7.4×）。
  凡隔离数据根，必须同时注入 `SVL_DML_MODEL` / `SVL_PATCH_ONNX` / `SVL_ISC_ONNX`，
  并**核对日志有 `BACKEND_SELECTED=DirectMLBackend`**（这行就是假慢探测器）。
- **S3 分区**：DrivenData 桶在 ap-southeast-1，用 us-west-2 拿 `PermanentRedirect`；
  该区 **HTTPS 握手本机失败（curl rc=35）但 HTTP 明文通** ⇒ 走 `http://<bucket>.s3.amazonaws.com`；
  列桶 `?list-type=2` + `continuation-token` 分页。
- **`raw.githubusercontent.com` 不可达（http=000），`api.github.com` 通** ⇒ 取仓库内文件走
  `Accept: application/vnd.github.raw` + `/contents/<path>`；**判断仓库存在性一律用 API**（本轮 4 个名字靠此判为不存在/写错）。
- **档案迁移脚本**：块内正文若含 `## P1 — Next` 这类字样，`str.index("## P1 — Next")` 会截在块中间
  ⇒ **锚点必须匹配行首**（`\n## P1 — Next`）。且断言要含**「章节数不变 + 无行内粘连标题」**——
  上一轮"行没丢但标题被粘"骗过一次，本轮 Edit 又写重过一次 `## P0 — Current`。
